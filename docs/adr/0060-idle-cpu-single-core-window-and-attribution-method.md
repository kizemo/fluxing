## 背景

ADR 0030 决策 2 把「空闲 CPU < 0.1%」立为发布验收条款，但同一张表的**判据栏**与**做法栏**互斥：

- 判据栏：「空闲 CPU **< 0.1%（占单核）**」；
- 做法栏：「静止 ≥ 8 s，两次 `CPU` 增量 / 窗口秒数 / **逻辑核折算**」。

两种口径在 20 逻辑核机上相差 **20 倍**。批次 AN 实测同一个进程同时得到 `0.039 %`（折算）与 `0.7804 %`（单核）——一个判「未破线」、一个判「破线」。同一份数据两个结论 ⇒ 判据不可执行。

同期取自 `docs/research/sogou-reverse-2026-11/REPORT.md` §5 的搜狗对照值「空闲 8 s 采样 CPU 0.78 %（单核）」是**单核口径**。若火流猩用折算口径判定，基线与对照物不同口径 ⇒ 跨机不可比 ⇒ 基线失去意义。

单核口径还有一个 ADR 0030 未察觉的测量学问题：`TotalProcessorTime` 源自 Windows 调度器记账，量化步长 ≈ 1 个时钟节拍（100 Hz ⇒ **15.625 ms**）。于是

| 静止窗口 | 1 个记账节拍换算成的百分比 | 能否判定 < 0.1 % |
|---|---|---|
| 8 s（ADR 0030 规定） | 0.195 % | ❌ 不可（地板已高于阈值） |
| 10 s | 0.156 % | ❌ 不可 |
| 16 s | 0.098 % | ✅ 刚好可 |
| 60 s | 0.026 % | ✅ 推荐 |

即：**ADR 0030 规定的测量方法（≥ 8 s）在单核口径下在原理上无法判定 < 0.1 %**。本轮实测到 `0.1561 %` 恰为 10 s 窗口内 1 个节拍、`0.0000 %` 为 0 个节拍，与该量化模型吻合。

## 决策

### 决策 1 — 空闲 CPU 口径统一为「占单核」

判据式固定为：

```
空闲 CPU %(占单核) = (ΔTotalProcessorTime / Δ墙钟秒) × 100
```

**不除以逻辑核数**。逻辑核折算值可作为附注打印，但**不作判据**。

阈值维持 **< 0.1 %（占单核）**，不下调。

与搜狗对照物的关系写明：搜狗 0.78 %（单核）⇒ 火流猩这条线比对照物严 **7.8 倍**。这是**有意的**——火流猩的产品目标之一就是系统占用低于搜狗（ADR 0030 决策 1 的「降低系统占用」）。代价是这条线必须在**长窗口**下测，否则量不出来（决策 2）。

### 决策 2 — 单核口径下的测量窗口下限 = 16 s

单核口径必须用 **≥ 16 s** 的静止窗口；ADR 0030 的「≥ 8 s」在单核口径下**作废**。

采样必须记录**实际计数值**（`ΔTotalProcessorTime` 的毫秒数）与窗口长度，避免把「1 个节拍」误读成真实占用、也避免把「0 个节拍」误读成「必然为 0」。

### 决策 3 — 性能归因必须有 A/B 对照，否则登记「不可归因」

任何形如「模块 X 造成内存增长 N MB」的断言，必须以**同机、同用户数据目录、同测量脚本、同采样窗口**的 A/B 对照（对照组 = 不含该模块的构建）为前提。

- 无对照 ⇒ 只能登记「不可归因」，**不得**写「增长由 X 造成」；
- 对照件必须先证明它**真的不含**该模块（字符串/符号判别），否则对照无效；
- **归档旧版本安装包可以充当对照件来源**——省掉一次「对照构建 + 装机」，前提是它落在同一功能边界之前。

## 后果

- ✅ 判据自洽：火流猩与搜狗的 CPU 数字同口径，跨机可比；
- ✅ 阈值与判据的关系写清，不再有「同一数据两个结论」；
- ⚠️ 空闲 CPU 从此必须长窗口测量，门禁脚本的采样窗口要跟着改（8–10 s 窗口在原理上无法判定 0.1 %）；
- ⚠️ 「1 个节拍 = 0.156 %」的量化地板会让 8–10 s 窗口的读数**看起来破线**，易被误读为真实回归——这是 ADR 0030 原文隐含的坑，现已显式化；
- ✅ 内存归因方法学落地：批次 AP 的 138.5 MB 归因正是按决策 3 做的（同机、同用户数据、同脚本、同窗口，A 组 = 当前含云构建，B 组 = 安装目录内 2026-11-08 的 `WeaselServer.exe.bakL` —— 经云标记字符串判别确认**不含任何云模块**；**`output/archives/fluxing-1.2.1-installer.exe` 已证伪为含云件，不可作对照**）。
- ⚠️ 对照件来源的判别纪律：不能用「版本号更老」推断「不含该模块」。批次 AP 实测 `fluxing-1.2.1-installer.exe`（2026-11-10 构建）**含** `/v1/sync/push` / `/v1/auth/login` —— spec 100 阶段 D 的云模块在 1.2.1 之前就已合入。**只有字符串/符号判别能证明对照件的身份**。

## 被否决的替代方案

1. **统一为「逻辑核折算」**：与搜狗对照值不同口径 ⇒ 基线不可比；且 0.1 % 在 20 核机上等于「单核 2 %」，等于事实上放弃这条线。否决。
2. **下调阈值到「单核 1 %」**：把「降低系统占用」这一产品目标的验收线放松到不如对照物的水平，属于自己放水。否决（保留 0.1 %，改为加长窗口）。
3. **保留两栏歧义、两种口径都记**：批次 AN 已证明这会产生「同一数据两个结论」，验收条款不可执行。否决。
4. **把内存归因交给 VMMap / 堆快照单独做**：堆快照能拆「谁占的」，但**拆不出「没有它会少多少」**；归因需要的是差值，而差值只能来自对照。否决（VMMap 可作辅助证据，不作归因依据）。
