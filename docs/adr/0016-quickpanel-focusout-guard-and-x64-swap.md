# 0016. 快速面板「常驻」的焦点守卫、64 位前端换装闭环，以及「先取事实再改码」的分期

- **状态**: Proposed
- **日期**: 2026-10-29
- **关联**: spec 087、任务总账本轮条目（T24 / T25 / T26 / T27）
- **相关**: ADR 0013（快捷设置栏常驻模式——本条补的是它**漏掉的一条**收起路径）、
  ADR 0015（左右约定的唯一来源——本条是它的**真机复测续篇**）、
  ADR 0014（CapsLock 锁存状态——与本条正交）

## 背景（Context）

1.1.0 装机后的第二轮真机复测（2026-10-29）带回三条新事实。

**缺陷 A —— 勾了「常驻」的面板仍然会消失。** 用户**确实勾上了**「快速面板常驻」
（这一项是上一条 spec 086 / ADR 0015 才补进输入法弹出菜单的），也**确实还在消失**。
逐点排查后发现：面板一共有 **9 个收起发起点**，其中 4 条**自动**路径都在
`WeaselServer/QuickPanelDialog.cpp` **内部**，并且逐条带着 `AlwaysShowMode()` 守卫
（`:682` 应用整体切换、`:740` 100 ms 轮询器、`:1317` `OnTimer(1)`、`:1326` `WM_KILLFOCUS`）。
另有 5 条是**需要用户明确手势**的路径（ESC `:1334`、`ToggleMode` 内 `:1453`、
`WeaselServer/WeaselServerApp.cpp:387` / `:401` / `:421`）。

唯独剩下的一条是**第四条自动隐藏路径**，而它**不是从面板内部发起的**：
输入法前端把「输入焦点离开」经由
`WeaselTSF/KeyEventSink.cpp:20` → `WeaselTSF/WeaselTSF.cpp:470-471` →
`WeaselIPC/WeaselClientImpl.cpp:178` → `WeaselIPCServer/WeaselServerImpl.cpp:272` / `:277` / `:474`
一路送到 `RimeWithWeasel/RimeWithWeasel.cpp`，在那里**裸调** `QuickPanelDialog::Hide()`
（`WeaselServer/QuickPanelDialog.cpp:1438` → `:1442` `ShowWindow(SW_HIDE)`）。
这条路径**绕开了面板内部的全部守卫** ⇒ 「常驻」看起来是全局生效的，实际不是。

1.2. **缺陷 B —— 64 位前端换装链路没闭环。** 换装是一条**三环相扣**的链：

```
装包期   版本化安装件 → $INSTDIR\weaselx64.<版本>.dll      ← 环节一
         失败则写 $INSTDIR\weaselx64.dll.stage2 标记
开机期   schtasks /Create /TR "cmd /c <bat>"               ← 环节二
         <bat> 内 copy /Y <源> $INSTDIR\weaselx64.dll        ← 环节三
```

三处各有一个缺陷，且**任意一处坏掉整条链就断**：

- 环节一：版本化安装件的拷贝**不覆盖**已存在的同名文件 ⇒ 每次装机都停在**上一版**的
  版本化件上（用户机上那个 `weaselx64.1.1.0.0.dll` 是上一次安装的产物）⇒ 直接掉进 stage2 分支。
- 环节二：开机补换的**任务登记命令引号断裂** ⇒ NSIS 的 `$"` 展开成**裸引号**（丢反斜杠），
  命令行变成 `/TR "cmd /c "C:\...\x.bat""` ⇒ `schtasks` 解析失败 ⇒
  **两个开机补换任务根本没被创建**（用户机上 `FluxingStage2Install` /
  `FluxingStage2InstallX64` **均不存在**）⇒ 这就是「连补换的痕迹都没有」的原因。
- 环节三：补换动作内部的拷贝命令**对单个文件是非法用法**（目录通配写法用在了文件目标上）。

1.3. **缺陷 C —— 裸 Shift 左右颠倒（事实链已收口到只剩一条）。** 上一条（ADR 0015）把
「0=左、1=右」的约定收敛到唯一一对函数，用户复测**症状与修复前完全一致**。
本轮用直连运行中管道的探针（`tmp/shiftprobe/shiftprobe.cpp`）证明**接收侧解码完全正确**
（bit0=0 → 第 2 个候选、bit0=1 → 第 3 个候选）；发送侧的左右判定**只有两个输入**：
虚拟键与物理扫描码（`include/KeyNameMapper.h:391-396`、`:551-554`，
位域见 `include/KeyEvent.h:3-15`）。⇒ 只剩「这两个输入在运行期与物理键不符」一种可能，
而这件事**只能靠一次真实按键**取到。

1.4. **缺陷 D —— CapsLock 不是缺陷。** 英文模式下按 CapsLock 进入**大写英文输入**、
不切回中文，是输入引擎的既定行为（`librime/src/rime/ascii_composer.cc:126-166`
+ `engine.cc:99-122`，`good_old_caps_lock: true` ⇒ 走 `kRejected` 中断处理器链）。
用户已裁定这是**正确规则**。真正的缺陷在**我们自己的复测单**：它让用户
「在 CapsLock 打开状态下测选候选 / 翻页 / 切中英 / 切标点 / 切简繁」，而那些状态下
引擎**整条链不响应** ⇒ 测出来的「失效」是**测法**的问题，不是代码的问题。

## 决策（Decision）

- **D1 —— 守卫加在调用点，不动「隐藏」动作本体。**
  `RimeWithWeasel/RimeWithWeasel.cpp:498-499` 变成
  `if (!QuickPanelDialog::AlwaysShowMode()) QuickPanelDialog::Hide();`。
  理由：`Hide()` 同时服务于 5 条**需要用户明确手势**的路径；把守卫放进 `Hide()` 内部
  会让这些路径在长显态下**全部失效**（与 ADR 0013 D7 冲突）。
  **守卫属于「这次收起是不是用户要的」这个判断，不属于「怎么隐藏」这个动作。**

- **D2 —— 只对「输入焦点离开」这一条路径设防。**
  面板内部那 4 条自动路径的既有守卫**逐条保留**（`:682` / `:740` / `:1317` / `:1326`），
  5 条手势路径**一条不动**。不做全局抑制位，不做「常驻态下禁止一切隐藏」。

- **D3 —— 版本化安装件的拷贝改用「`File /oname=` 改名 + 显式覆盖」，32 位与 64 位两支同改。**
  `output/install.nsi:633-638`（32 位）与 `:694-698`（64 位）改成
  `Delete <陈旧版本化件>` + `SetOverwrite on` +
  `File /nonfatal /oname=weaselx64.${FLUXING_VERSION}.${WEASEL_BUILD}.dll "weaselx64.dll"`
  + `SetOverwrite try`。理由：拷贝指令**没有改名能力**，必须用 `File`；
  而 NSIS 的改名语法**只有 `/oname=`** —— `File "src" "dst"` 会被 `makensis`
  解释成「两个待打包的输入文件」，报
  `File: "weasel.1.1.0.0.dll" -> no files found.` 并中止（**本轮打包实测**）。
  写前先 `Delete` 掉上一版的版本化件，是因为它**可能仍被运行中的进程映射**，
  直接覆盖写会失败；`/nonfatal` 把失败变成错误位 ⇒ 降级到开机补换，而不是中止安装。

- **D4 —— 开机补换脚本落到无空格路径，任务登记命令因此不需要内层引号。**
  脚本改写 `$WINDIR\Temp\fluxing-stage2-install.bat` / `…-x64.bat`
  （`output/install.nsi:1062` / `:1088`），`schtasks /TR` 里直接写
  `cmd /c $WINDIR\Temp\fluxing-stage2-install.bat`（`:1070` / `:1095`），
  **不带内层引号**。理由：在 NSIS 里拼转义反斜杠是**与工具链搏斗**
  （`$"` 会把反斜杠吃掉），而把路径挪到**无空格**处就**根本不需要引号**。

- **D5 —— 补换脚本内的拷贝改成逐文件覆盖式拷贝。**
  `xcopy /Y /Q "src" "dst*"` → `copy /Y "src" "dst" >NUL`
  （`output/install.nsi:1064` / `:1090`）。理由：`*` 只在**目录通配**时成立，
  对**单个文件**是非法用法。

- **D6 —— 补换脚本的拷贝源在安装期就展开成绝对路径。**
  批处理里原先写的是 cmd 的 `%TEMP%\fluxing-staged\...`，开机时按 **SYSTEM** 的
  `%TEMP%`（= `C:\Windows\Temp`）解析，而待替换文件是在**安装期**用 NSIS 的 `$TEMP`
  （安装用户的临时目录，`output/install.nsi:585-586` / `:1050` / `:1083`）暂存的
  ⇒ 两者**不是同一处**，开机补换会**找不到源文件**。
  本轮把 NSIS 的 `$TEMP` 在**安装期**就展开进批处理文本（`FileWrite` 里的 `$TEMP`
  是 NSIS 变量，不是 cmd 的 `%TEMP%`）⇒ 批处理里留下的是**绝对路径**，
  开机后 SYSTEM 照着这个绝对路径取文件。
  边界说明：本条只保证**四环的语法与路径都成立**；**真机是否真的换掉**仍待装包复测
  ⇒ ADR 0016 保持 `Proposed`（与「门禁没跑出来的数字不许编」同一条规矩：
  没验过的环节不许写成已验好）。

- **D7 —— 裸 Shift 的方向判定本轮不动代码。**
  交付物是**一次按键即可出结论**的观测工具（`tmp/shiftprobe/shiftside.cpp`：
  `WH_KEYBOARD_LL` 低级键盘钩子取 `KBDLLHOOKSTRUCT::scanCode`（物理 0x2A=左 / 0x36=右）
  与 `vkCode`（操作系统认知），再用 `fluxing::ResolveCharacter` 复算前端的键名），
  以及把「观测结果 → 修复形态」的**判据写死**在 spec 里。
  理由：宪法 R1（先定意图与验收）。此时改码有**两种互斥的形态**
  （按物理扫描码判定 / 提供「左右互换」开关），形态选错就是白改一轮。

- **D8 —— CapsLock 不改码，只改语义表述与复测口径。**
  在用户可见文档里写清「英文模式下按 CapsLock 进入大写英文输入、不切回中文是正确行为」，
  并把复测单改成**在 CapsLock 关闭状态下**执行选候选 / 翻页 / 切中英 / 切标点 / 切简繁。

- **D9 —— 输入法弹出菜单仍然不加勾选标记（沿用 ADR 0015 D7）。**
  勾选态目前只回填到托盘图标菜单（`WeaselServer/WeaselServerApp.cpp:29` →
  `WeaselServer/WeaselTrayIcon.cpp:32` `CheckMenuItem`），
  语言栏弹出菜单 `WeaselTSF/LanguageBar.cpp:185` 裸调 `TrackPopupMenuEx`、**无回填**。
  本条**只记录**该缺口，不扩协议。

## 后果（Consequences）

- **修好了什么。** 勾上「快速面板常驻」之后，**切换到别的窗口再切回来**，快捷设置栏**还在**；
  而 Esc / 收起快捷键 / 点菜单项 / 关掉「常驻」本身**照旧能收起**。
  64 位程序里的输入法换装：**版本化安装件这一次真的会被覆盖成新版本**；
  当场被占用而换不掉时，**开机补换任务会被真正创建**，脚本里的拷贝命令**合法可执行**。

- **用户可能察觉到的变化。** 切窗口不再让面板消失。安装包在 64 位机器上会**多一次覆盖**，
  并且开机补换的痕迹（任务登记）会**真的出现在系统里**。

- **刻意不修的东西。** 弹出菜单的勾选标记仍没有（D9）；CapsLock 的引擎行为不变（D8）；
  裸 Shift 的方向**本轮没动**（D7）。

- **为什么「常驻」这个缺陷能活到现在。** 「常驻」开关**看起来**是全局生效的，
  而实际有**四条**自动隐藏路径散在**两个地方**（面板内部 3 条 + 外部进来 1 条），
  前一条只覆盖了**面板内部**那几条 ⇒ 验收项写「勾上后不自动隐藏」时，
  只要在面板上自测就会通过，**换一个窗口再回来**才会暴露。
  ⇒ 教训：这类「总开关」必须按**发起点逐条列**才能验全，不能只验**当前可见的那一处**。

- **为什么换装缺陷能活到现在。** 上一条把它定性成「装机时文件被占用 ⇒ 留标记 ⇒ 开机补换」，
  **结论方向对，但只验了第一环**。后两环（任务登记、开机执行）**从未被真正验证过**，
  于是一条链上**三个缺陷叠在一起**，表面症状只有一个。
  ⇒ 教训：链路型缺陷要**逐环验证**，且「用户机上没有痕迹」这件事本身**就是一条证据**。

- **本条自身变更的风险。** 小而有限：一个调用点加一条判据（1 个文件）、
  安装器两支各一处拷贝写法 + 两处脚本落点 + 两处命令语法。
  面板的 `Hide()` 本体、Shift 状态机、候选选择逻辑、键名映射**全部未动**；
  输入引擎**未动**（宪法 P3）。

- **本条引入的风险。** 补换脚本的**拷贝源**已改成安装期展开的绝对路径，
  开机时 SYSTEM 照绝对路径取文件 ⇒ 「找不到源文件而什么都不做」这一类
  静默失败被消除；但**真机是否真的换掉**仍待装包复测（ADR 0016 保持 `Proposed`）。

## 证据（Evidence）

- **面板守卫的静态复核**：`RimeWithWeasel/RimeWithWeasel.cpp:498-499` 已加守卫；
  `WeaselServer/QuickPanelDialog.cpp:682` / `:740` / `:1317` / `:1326` 的既有守卫**未变**；
  5 条手势路径**未变**。
- **换装链路的逐环对照**：`output/install.nsi:633-638`、`:694-698`（拷贝）、
  `:1062` / `:1070`、`:1088` / `:1095`（脚本落点与任务登记）、
  `:1064` / `:1090`（拷贝语法与拷贝源）—— 本条**只改**这三类，其余一字未动。
- **打包实测（把「改名语法」这件事钉死）**：第一版把拷贝写成
  `File "weasel.dll" "weasel.1.1.0.0.dll"`，`makensis` 当场报
  `File: "weasel.1.1.0.0.dll" -> no files found.` 并中止 ⇒ **`File` 的两参写法不是改名语法**，
  唯一改名语法是 `File /oname=<新名> <源文件>`。改成 `/oname=` + `/nonfatal` 后打包通过（installer 42,763,200 B）。
- **「什么都没发生」也是证据**（`SetOverwrite try` 静默跳过）：`SetOverwrite try` 在目标被占用时
  **跳过且不置错误位** ⇒ 原代码的 `File "weaselx64.dll"` + `IfErrors 0 weaselx64_done` **直接跳走**，
  版本化分支**根本没被执行到**、`.stage2` 标记也**没写** ⇒ 旧二进制留在盘上。
  本轮改为：**Rename 失败就直接进版本化分支**，不再用错误位去探测「文件是否被占用」。
- **Shift 的运行时探针**：`tmp/shiftprobe/shiftprobe.cpp` 直连运行中的服务，
  参考轮与实验轮各两轮 ⇒ **接收侧正确**。
- **用户机现状（取证时刻）**：`weasel.dll` = 1,655,808 B / 2026-10-28 22:32:38
  （SHA256 前 16 位 `1BBEA1114229357E`，与 `output\weasel.dll` 一致 ⇒ **32 位已是新件**）；
  `weaselx64.dll` = 1,955,840 B / 2026-10-27 23:50:56
  （`28064A26D461F8A2`，**旧件**）；`weaselx64.1.1.0.0.dll` = 1,956,352 B /
  2026-10-28 20:50:26（`2112A2985C74298A`，上一次安装的版本化件）；
  `output\weaselx64.dll` = 1,956,352 B / 22:33:10（`3EC646D068E7110D`，**新件**）；
  `WeaselServer.exe` = 2,231,808 B / 22:32:56（`830E485E66150C81`，与
  `output\Win32\WeaselServer.exe` 逐字节相同，运行中进程 pid 32304）。
  ⇒ **64 位仍旧、32 位已新**，与 D3 修的是同一件事的证据吻合。
- **沙箱权威门禁在本机跑不起来**（`run-verify.cmd` exit 4、`sandbox-artifacts\rime\logs\`
  下无 `boot.log`）⇒ 本条**没有门禁数字可贴**，不编造。

## 未决问题（Open questions）

- **Q-087-1（已定：取候选 ①）**：开机补换脚本里的**拷贝源**路径怎么定？
  两个候选：① 安装期把暂存目录**展开成绝对路径**写进脚本；② 统一把暂存目录放到
  `$WINDIR\Temp\fluxing-staged`（与脚本同处，开机时的 `%TEMP%` 就对得上）。
  **本轮取 ①**：`FileWrite` 里的 `$TEMP` 是 NSIS 变量，在**安装期**就展开成绝对路径，
  开机时 cmd 里的 `%TEMP%` 就不再参与解析 ⇒ 不依赖开机上下文的环境变量。
  残留边界：**真机是否真的换掉**仍待装包复测（tasks T016）。
- **Q-087-2**：裸 Shift 的物理左右事实未取得（`shiftside.exe` 未跑）⇒ 修复形态二选一未定
  ⇒ 方向修正不在本条。
- **Q-087-3**：输入法弹出菜单要不要显示常显开关的当前状态？
  需要新增「查询状态」的往返消息 ⇒ 协议扩张 ⇒ 单独的条目。
- **Q-087-4**：沙箱权威门禁在本机仍跑不起来 ⇒ 本条的产物级门禁**缺失**，
  需要在能跑通沙箱的环境里补一次。
- **Q-087-5**：64 位程序的注册项仍指向**未版本化**的文件名
  （HKLM 64 位 `Classes\CLSID`）⇒ 版本化安装件装成后，仍需「注册」这一步成功改写它才生效
  （`output/install.nsi:698` 附近的注册调用）；该步失败会退回开机补齐路径。
