# 0039. 云端账号与多端同步：Cloudflare Workers + R2/D1 后端，客户端用系统自带能力，端到端加密，合并落在客户端

- **Status**: Accepted
- **Date**: 2026-11-07
- **Deciders**: Fluxing maintainers
- **Related**: spec `100-fluxing-cloud-account-sync`（`spec.md` / `plan.md` / `tasks.md`）、spec `010-cloud-sync`（技术结论作废，仅留历史）、constitution §P2 / §P3 / §P5 / §P7、ADR 0030（性能基线）、ADR 0034（账号页入口）、ADR 0037（词库导入）

## Context

用户 2026-11-07 要求进入「用户登录 + 同步配置」阶段，并指定用 Cloudflare 承载云端，
让用户把**自己造出来的输入法资产**（个人词库、用户短语、个人配置）存到云端并在多端之间保持一致。
用户当天拍板四条前置决策：**① 登录 = 邮箱 + 密码，在客户端输入 ② 云端数据全量端到端加密
③ 官方统一端点（项目方运营）④ 冲突按条目合并。**

约束把可行空间压得很窄：

- **仓库现状**：实测 `WinHttp|WinINet|HttpSendRequest|InternetOpen|curl_easy` **全零命中** ——
  仓库里根本没有 HTTP 客户端。spec `010-cloud-sync` 设计的 libcurl **并不存在**。
- **宪法 P3 / NFR-004**：不得新增第三方依赖 ⇒ 网络、加密、凭据都只能用操作系统自带能力。
- **宪法 P2**：TSF 回调内禁止阻塞 I/O ⇒ 同步不能挂在输入链路上。
- **宪法 P7 / ADR 0030 三数字**：不新增常驻进程、内存 < 40 MB、空闲 CPU < 0.1%。
- **免费额度实测**：Workers 10 万请求/天；Workers KV 读 10 万/天但**写仅 1000 次/天**；
  R2 10 GB 存储 + 零出口费；D1 500 万行读/天、10 万行写/天。KV 的写额度会被同步热路径瞬间打穿。
- **隐私红线**：输入内容永不上云；未登录时出向请求数必须为 0。

## Decision

1. **后端 = Cloudflare Workers + D1 + R2，排除 KV。**
   D1 只存账号 / 设备 / 令牌 / 同步**索引元数据**（哪条目、什么版本、对象在哪）；
   R2 存**密文本体**，桶 `fluxing-sync`，对象键 `u/<account_id>/<sha256(item_key)>`。
   KV 因写额度（1000/天）被排除出同步热路径。

2. **客户端只用系统组件：WinHTTP（网络）+ Windows CNG（PBKDF2 / HKDF / AES-GCM）+ Credential Manager（凭据）。**
   不引 libcurl、不引 OpenSSL、不自己实现 Argon2id 或 PAKE。仓库原本零 HTTP 客户端这一事实
   被记录进 ADR 索引与 `plan.md`，避免后来者再次假设 libcurl 存在。

3. **密钥分离：`auth_key` 上传，`enc_key` 永不上传。**
   `master = PBKDF2-HMAC-SHA256(password, salt, 600000)`，再 HKDF 派生 `auth_key`（登录用）与
   `enc_key`（加密用）。服务端只存 `verifier = HMAC-SHA256(server_pepper, auth_key)`，pepper 存 Workers Secret。
   ⇒ 服务端被完整攻陷（含 Secret）仍读不到同步内容明文，最多能冒充用户登录。

4. **定序用混合逻辑时钟（HLC：`ms` + `counter` + `device`），合并在客户端完成。**
   服务端只见密文，**物理上无法**按条目合并。`config` 整份取 HLC 较大者；
   `phrases` / `userdb` 按条目键合并（异键并集、同键取新）后**重新加密并回传**，使两端收敛。

5. **同步引擎挂在既有唯一常驻进程 `WeaselServer` 的后台线程内，不新增任何 IPC 消息。**
   账号页与引擎同进程 ⇒ 直接函数调用 ⇒ 不触发 IPC 四边同步（server / TSF / deployer + ADR + `test/TestWeaselIPC`）。
   **触发条件**：若将来要在 `WeaselDeployer` 里加账号入口，那时才新增 IPC 消息并走四边同步流程（首版明确不做）。

6. **首版不做**：找回密码、改密、网页端管理、团队 / 家庭组织账号、输入历史上云。
   账号**只用于同步**，不做社区 / 排行 / 广告 / 行为统计。

7. **词库合并语义先取证后实现。** 导出 / 导入的格式与同名词条覆盖规则**不得凭推测**，
   必须先产出可复跑证据（spec 100 的 `tasks.md` T102）才允许写合并代码。

## Consequences

- ✅ **零第三方依赖**：WinHTTP / CNG / Credential Manager 全是操作系统组件，符合 P3 与 NFR-004。
- ✅ **TSF 侧零感知**：同步全部在 `WeaselServer` 后台线程，输入热路径零改动，无 IPC 协议变更。
- ✅ **不新增常驻进程**：进程数仍为 1，内存与 CPU 基线不被结构性破坏（ADR 0030）。
- ✅ **服务端失陷不泄内容**：DB 脱库（拿不到 pepper）不能离线验口令，也读不到明文；
  全陷（含 Secret）仍读不到内容，只多一条「冒充登录」风险。
- ⚠️ **诚实边界**：「内容机密」与「账号隔离」是两件事 —— 完全攻陷下可冒用账号。该边界必须写进
  账号页与本 ADR，不许用「端到端加密」一句话含糊带过。
- ⚠️ **口令弱 ⇒ 字典攻击面**：补偿手段是口令强度下限 + 可选「独立于登录口令的同步口令」+
  界面明示「口令遗忘 = 云端数据不可恢复」。
- ⚠️ **E2EE + 口令遗忘 = 数据永久不可恢复**：首版不做改密（改密会牵动全量重加密）。
- ⚠️ **HLC 与合并是新增的复杂度热点**：必须下沉为纯逻辑（`include/FluxingCloudEnvelope.h`），
  生产与单测**同源**，并带反例断言（乱序 / 同版本 / 空载荷 / 超长载荷）。
- ⚠️ **引入出向网络能力触碰既有红线**：未登录 ⇒ 引擎不启动、账号页零请求；
  门禁须有一条「未登录时出向连接数为 0」的断言。
- ⚠️ **境内可达性未知**：首版用自有域名而非平台默认域名，端点可达性进 T103 取证，
  失败一律降级不阻断。
- ⚠️ **spec 010 的技术结论作废**（Vercel + Postgres + libcurl + 服务端见明文 + LWW）：
  010 仅保留作历史依据，**任何实施都不得引用其技术结论**；010 的 spec 首页已加取代指针。
- ℹ️ **本决策可部分回退**：换后端（R2/D1 → 其它对象存储）不动客户端契约；
  改合并策略只动纯逻辑头 + 单测；但「E2EE + 客户端合并」这条主轴一旦上线，
  改回服务端明文意味着数据模型重做。
