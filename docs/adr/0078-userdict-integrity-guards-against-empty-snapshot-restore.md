# ADR 0078 —— 用户词典「假空 / 空快照还原」数据完整性护栏

- 状态：**Accepted**（客户端段；服务端与 rime 侧均不动）
- 批次：**P0 词典完整性批次**（由 BR-①g §P-O 派生的独立批次）
- 触发：BR-①g v5 稳态轮（2026-11-26 10:23–10:53）出现三条新发现之三 ——
  「本地词典读成空」，且同轮发现本地与云端两侧的词条载荷呈**整库统一值**。
- 上游指针：`docs/archive/handoffs/handoff-2026-11-23-batch-br-write-amplification-and-zero-write-register.md`
  §P-O / §P-O.14；`docs/adr/0077-bucket-level-sync-storage-architecture.md`；`.specify/specs/103-client-bucket-sync/spec.md`

---

## 1. 背景与问题

BR-①g 客户端桶化（ADR 0077）把同步从「条目级」搬到「桶级」，但**用户词典的读写通道
始终是 rime 的 `backup_user_dict` / `restore_user_dict`**（真相源：
`docs/research/fluxing-cloud-2026-11/userdict-merge-semantics.md` = T102）。
这条通道有三个已知语义（**不可改**：rime 侧实现不在本仓）：

1. 导出 = 快照文件（含墓碑 / dee / 逐条 tick / `/tick`）；
2. 还原 = 内部即 `UserDbMerger`：`abs(commits)` 择优、`dee` 取 max、`tick` 抬升、
   `/user_id` 被本地覆盖 ⇒ **幂等**；
3. **不能用** `export_user_dict` / `import_user_dict`：那对原语会丢 `dee`/`tick`、
   跳过墓碑、把 `-1` 放大成 `-2`、把 `0` 写成垃圾条目，还会给不存在的库静默建库。

于是「空快照 / 假空」这一类故障，**在通道层没有任何护栏**：我们的代码负责决定
「导出什么、还原什么」，而 rime 只会照单全收。

## 2. 已证事实（本批取证，盘上实测）

> 取证脚本与原始输出：`reports/fluxing-br-1g/p0-scan-leveldb.ps1` /
> `p0-scan-leveldb.out.txt`、`p0-sidecar-diff3.ps1` /
> `p0-sidecar-diff3.out.txt`（均不入库）。

### 2.1 导出侧确实存在「空内容也算成功」的口子

`WeaselServer/Cloud/CloudRimeUserDictBackend.cpp`（改动前 :362-385）：
`SafeBackupUserDict` 返回 true → `ReadFileText` 成功（**文件存在但内容为空也返回 true**）
→ `out->append(text)`（追加空串）→ **`++exported` 无条件自增**。
⇒ 「备份文件为空 / 只有元信息行」会被当成「这个词典导出成功」。
**出口只看 `exported == 0`，不看内容。**

### 2.2 还原侧确实存在「空段也照还原」的口子

同文件（改动前 :406-444）：按 `#@/db_name` 切段 → 每段写临时文件 →
`SafeRestoreUserDict` ⇒ **不校验该段有没有数据行**。
⇒ 一个只有元信息行（或 0 行）的段会被送进 rime 的 `UserDbMerger`。

### 2.3 本地与云端两侧的载荷都已是「整库统一值」

云端快照缓存（解密后的明文）`…\sync\<uid>\rime_ice.userdb.txt`
（4,794,399 B / **94,604 数据行** / 2,804 个不同 value 串 / mtime 2026-11-26 10:50:18）：

| value 串 | 行数 |
|---|---|
| `c=100 d=1.12192e-66 t=27610` | **90,778** |
| `c=100 d=1.88622e-31 t=27610` | 931 |
| `c=100 d=1.12193e-66 t=27610` | 64 |
| `c=-1 d=0 t=27610`（墓碑） | 10 |
| `c=1` / `c=2` / `c=3` …（自然学习值） | 284 / 26 / 7 / … |

本地词典 leveldb（`rime_ice.userdb`，5 个 .ldb/.log 共 10,527,259 B）逐文件扫描
（`p0-scan-leveldb.out.txt`）：**5 个文件全部**以 `c=100` 为主
（39,430 / 39,572 / 13,209 / 57,522 / 34,675 处），`d=1.12192e-66` 同比例，
`t=27610` 覆盖绝大多数条目；历史层仍留有少量自然值（`c=1` 约 560 处、`c=2` 约 51 处）。
live leveldb 上下文中「阿明工具箱」的 value 即 `c=100 d=1.12192e-66 t=27610`。

⇒ **两侧同值 ⇒ 该状态是自持的（本地导出→上云→还原→再导出），不是单侧漂移。**

### 2.4 侧车 `s2:` 反推 ⇒ **污染早于桶化批次**（本轮回填）

侧车格式真相：`fluxing-cloud-sync.state` 共 **93,278** 行 row，行式 =
`row<TAB>item_key<TAB>ts<TAB>idx<TAB>legacy_hash<TAB>s2:hash`（**6 字段**；
item_key 内部的制表符被转义成**字面 `\t`**，故 dict/phrase 需按字面 `\t` 二次切分）。

按 `s2:` 列反推本地载荷形态（脚本 v3，样本 4,000 行）：
**3,848 行匹配 `c=100`**、54 行 `c=101`、27 行 `c=1`、8 行 `c=2`、3 行 `c=0`、
1 行 `c=15`、59 行 NO_MATCH。
侧车 `ts` 范围 = **2026-11-25 00:06:29 .. 2026-11-26 02:37:11**。

⇒ **整库统一 `c=100` 在 2026-11-25 00:06 就已存在** ⇒ 该状态**早于**桶化批次
（BR-①g 客户端段 2026-11-25 下午才开始落码）⇒ **不是 v5 / 桶化造成的**。
⇒ 本 ADR 与 v5 写放大、桶化门禁**无因果关系**（两条独立的线）。

### 2.5 侧车 legacy 哈希列 = **惰性兼容列**（本轮回填，纠正早期误读）

全表 93,278 行的 `legacy_hash` 列**只有 1 个不同值** `c7cc011f1b29de53`
⇒ 该列**不是逐行哈希**。经查生产实现：写入侧 `CloudSyncService.cpp:1694 / :1712 / :1829`
写的是 `s2:` 语义哈希，读取侧 `:2568` 取的是 `cols[5]`（`s2:` 列）
⇒ `legacy_hash` 列**当前不被读、写的是常量** ⇒ **不得**把它当作写放大的根因
（该线索**未坐实**，不作为本批结论）。

### 2.6 归因边界（**仍未坐实**，不得当结论）

- 「整库统一 `c=100` / `dee≈0` / 同一 `tick`」这一形态 ⇒ **某一次还原把整库写成了
  同一个值**（tick 抬升 = T102 的 `tick 一律抬到 max_tick_`；`abs(commits)` 择优 ⇒
  写进去的值来自那一轮输入的快照）。
- **但「那一轮输入的快照为什么已经是统一值」没有坐实**：
  ① rime 侧 `userdb.cc` **不在本仓**（librime 子模块只有头文件）⇒ 无法从源码归因；
  ② 盘上**没有任何未污染的历史快照**可比对；
  ③ 污染时点**落在 2026-11-25 00:06 之前**（§2.4）⇒ 桶化 / v5 均在其后。
- ⇒ 本 ADR **不写**「污染由我方某次还原造成」之类的结论；也**不做**任何
  「清洗/重建用户词典」的动作（那是删用户数据，必须由用户拍板）。

### 2.7 与 §P-O 的关系（不冲突）

§P-O.5 的「整库还原 ⇒ 指纹全变 ⇒ 全量重推」因果链**仍然对不上**
（回滚后两轮 `matched=67` 同值）。本 ADR 处理的是**另一条线**：
「空 / 退化快照会不会被推上云、或被还原进本地」——它与「稳态零写不成立」互不依赖。

## 3. 决策

### D1 —— 通道不变，不改 rime 侧

传输通道维持 `backup_user_dict` + `restore_user_dict`；**不新增第二套 payload
解析器**（宪法 R7）；**不改 librime**（不在仓内，改了也带不走）。

### D2 —— 导出侧：空内容**不算**导出成功（落点 = rime 后端）

`ExportUserDict` 逐词典判定：备份文本必须**含至少一条数据行**。
- 空 / 只有元信息行 ⇒ **跳过该词典**（计入 `export_empty_skipped`），不追加进 `out`；
- 所有词典都被跳过 ⇒ **导出失败**（中文原因：「用户词典备份失败：备份内容为空。」）
  ⇒ 本轮**不推送任何用户词典内容**。

> **既有语义不变**：改动前「备份文件为空」会让 `exported` 自增 ⇒ 导出「成功」但
> 内容为空 ⇒ 随后的快照解析失败 ⇒ **本轮同样失败**。本批只把失败点前移并把
> 中文原因说准（「备份内容为空」而不是「快照内容为空」），**不改变轮次结果**。

### D3 —— 还原侧：0 数据行的段**拒绝还原**（落点 = rime 后端）

`ImportUserDict` 逐段校验：段内必须至少有一条数据行。
- 0 数据行 ⇒ **不写临时文件、不调 `restore_user_dict`**，计入 `import_empty_rejected`；
- 全部段被拒 ⇒ 失败（「用户词典还原失败：快照内容为空。」）。

### D4 —— 写回侧：空合并集**不得**覆盖本地（落点 = 服务层）

`CloudSyncService.cpp` 回写路径：写回文本 0 数据行 ⇒ **跳过回写**
（**不是**整轮失败：拉取与推送仍可继续），并记诊断行。
> 现状里 `changed` 为 false 时本就不写；本条是「合并集为空但 changed 为真」的
> 显式拒绝（纵深防御），防止将来合并语义变化时用空快照盖住本地词典。

### D5 —— **服务层不得因「本地为空」判本轮失败**（本轮新增 · 纠正早期草稿）

早期草稿曾让服务层在「本地导出 0 数据行」时**整轮失败**（原因「用户词典备份内容为空，
本轮已跳过同步。」）。**该设计已推翻**，理由：

1. **它会掐断「新设备从云端还原」这条正常路径**：本地为空 + 云端有内容时，
   正确行为是**拉取并还原云端内容**（`local_entries` 为空 ⇒ 推送集合自然为空 ⇒
   空快照**本来就不会**被推上云，护栏在此处没有额外收益）；
2. **在生产里它不可达**：D2 已保证 rime 后端的导出要么失败、要么至少含一条数据行
   ⇒ 服务层看到 0 数据行的路径只在**非 rime 后端**（单测假后端）下出现；
3. ⇒ 服务层改为**只记诊断行**（`userdict export_empty_local=1`），**不判失败**。

### D6 —— 判据口径唯一化（落点 = 共享层 `CloudUserDictIo`，宪法 R7）

新增两个**生产内**函数，导出侧与还原侧共用（不新增第二套行解析器）：

| 函数 | 作用 | 落点 |
|---|---|---|
| `CountUserDictDataRows(text)` | 统计快照文本里的**有效数据行**条数（口径复用 `ParseUserDictSnapshots`） | `CloudUserDictIo.{h,cpp}` |
| `FilterUserDictTextsByContent(texts, out, skipped)` | 过滤掉 0 数据行的段，返回保留段与被丢弃计数 | `CloudUserDictIo.{h,cpp}` |

两个护栏落点都调用同一份函数 ⇒ **判据口径单一**（R7），且**可进单测**。

### D7 —— 无条件诊断行（不含任何条目明文）

新增（ADR 0066 已坐实：没有调试器时 `OutputDebugStringW` 抓不到 ⇒ 必须写文件）：

| 诊断行 | 落点 | 含义 |
|---|---|---|
| `userdict export_empty_skipped=N` | rime 后端 | 本次导出被跳过的空词典数 |
| `userdict export_empty_local=1` | 服务层 | 本轮本地导出 0 数据行（**不判失败**，见 D5） |
| `userdict import_empty_rejected=N` | rime 后端 / 服务层 D4 | 被拒绝还原 / 被跳过写回的空快照数 |

**绝不落词条明文**，只落计数。

### D8 —— 门禁用例（`test/TestFluxingCloud`，生产与单测同源）

| # | 用例 | 期望 |
|---|---|---|
| ① | 空文本 / 只有元信息行 | `CountUserDictDataRows` = 0（假空被识别） |
| ② | 有效数据行 / CRLF 文本 | 计数正确（1 / 2 / 1） |
| ③ | 形态非法行（BM / ADR 0071 口径） | 不计入（不回归） |
| ④ | 无 `#@/db_name` 段 | 计数 = 0（无法定位词典） |
| ⑤ | `FilterUserDictTextsByContent` 混合输入 | 保留有效段、计数被丢弃段；一段不留 ⇒ 返回 false |
| ⑥ | 服务层：本地为空 + 远端为空 | 本轮**成功**、推送 0 条、**不调** `ImportUserDict`（空合并集不覆盖本地） |
| ⑦ | 服务层：本地为空 + 远端有内容 | 本轮成功、**回写 1 次**且回写文本非空（还原路径未被掐断 · D5） |
| ⑧ | 服务层：本地 1 条 + 远端 1 条 | 回写文本 **2 条**数据行（合并保留本地条目 · 不回归） |
| ⑨ | 服务层：含形态非法行 | 本轮仍成功、回写 2 条（非法行被跳过、不毒化整轮） |

### D9 —— 真机验证纪律

只跑 **phase 1 / phase 2**；**不得进 phase 3**（硬前置 = 云端历史 40,061 条先完成
桶化覆盖，见 handoff §O-1.1 / ADR 0077:411-412；且规则 1 盲区未修 ⇒ 阶段 3/4 后
半库存回推会静默删云端条目、不可逆）。
起跑前必须：`Test-Path` 自检 exe 路径、`Restart` **先起后杀**、等本地词典
leveldb **连续两次 60 s 快照不变**（静默）再动手；**不得裸杀** WeaselServer
（会重置 `startup_pending_`，把下一轮变成 kPullOnly 启动轮）。

### D10 —— 用户数据的处置边界

本批**不清洗、不重建、不删除**任何用户词典数据（那是不可逆的删用户数据）。
「整库统一 `c=100`」这一形态**只登记 + 只加护栏 + 只加诊断**；
是否重建由用户单独拍板（需要独立批次 + 独立备份策略）。

## 4. 影响面

- 改动面：
  - `WeaselServer/Cloud/CloudUserDictIo.{h,cpp}`：新增 `CountUserDictDataRows`
    与 `FilterUserDictTextsByContent`（**唯一判据口径**）；
  - `WeaselServer/Cloud/CloudRimeUserDictBackend.cpp`：导出侧（D2）/ 还原侧（D3）
    护栏 + 诊断行（**纵深防御**：该文件不进单测工程 ⇒ 其判定逻辑由共享层函数
    在单测里覆盖，**接线**由真机轮覆盖）；
  - `WeaselServer/Cloud/CloudSyncService.cpp`：服务层只记诊断（D5）+ 写回侧空集保护（D4）；
  - `test/TestFluxingCloud/TestFluxingCloud.cpp`：门禁用例（D8 ①–⑨）。
- 不改动：服务端（`cloud/fluxing-sync/**`）、librime、侧车格式、桶协议、用户数据。
- 对既有功能的影响：**只在「快照为空 / 退化」这一条路径上从「静默成功」改为
  「显式拒绝 + 显式诊断」**；正常路径零行为变化（D8 ②③⑧⑨ 锁死）；
  「本地为空 + 云端有内容」的还原路径**明确不受影响**（D8 ⑦ 锁死）。

## 5. 取证缺口（**未闭环**，登记）

1. rime 侧 `userdb.cc` 不在仓 ⇒ 「统一 `c=100`」的最终归因不可得；
2. 盘上无未污染历史快照 ⇒ 污染发生时点不可定（只知**早于** 2026-11-25 00:06）；
3. 「本地词典读成空」与「整库统一值」是否同源（前者是**导出读空**，后者是**载荷形态**）
   **仍未区分** ⇒ 不得合并叙述；
4. 「整库统一 `c=100`」是否就是该用户 rime_ice 库的**原生形态**（批量导入 / 统一
   学习值）**未排除** ⇒ 本批只登记 + 加护栏，**不断言它是污染**；
5. 侧车 `legacy_hash` 常量列的**写入来源**未查清（当前写 `s2:`、读 `cols[5]` ⇒
   该列惰性）⇒ 不作为写放大根因登记。
