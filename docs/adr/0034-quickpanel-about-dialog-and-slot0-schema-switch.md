# 0034. 快捷设置栏第 4 槽承载「关于 / 账号说明」页，第 1 槽切换输入方案；版本与产品名的唯一真相源是宿主 exe 的 PE 版本资源

- **状态**: Accepted
- **日期**: 2026-11-04
- **决策者**: Fluxing maintainers
- **相关**: spec 099（参考逆向搜狗输入法优化快捷设置栏）P0-3；ADR 0013 / 0024 / 0029（快捷面板）；constitution P2 / P5；lessons-learned L175 / L177 / L178

## Context

快捷设置栏（`QuickPanelDialog`）自 v0.19.0.62 起是 4 槽布局
（`kButtonCount = 4`）：0 Schema / 1 Phrase / 2 Settings / 3 Account。
其中**两槽是死槽**：

- **槽 0（Schema）**：`ShowQuickPanel()` 把它接到
  `ShellExecuteW(WeaselDeployer.exe, L"/hotkey")` —— 拉起另一个进程的
  热键编辑器。这条路径有两个问题：其一，`/hotkey` 在**全仓是唯一一处**
  调用点，是典型的死代码；其二，「拉起另一个 exe 的窗口」既不是确定的用户
  可见效果，也把面板的语义外包给了一个与面板无关的旧工具。
- **槽 3（Account）**：`onLogin` 传的是空 lambda，点下去什么也不发生。

spec 099 P0-3 的验收条款是「**每个可见槽位点击必产生确定的用户可见
效果**」。两条死槽直接违例。

同时，搜狗同类面板的第 4 槽是「账号 / 关于」入口。对本 fork 而言，
**没有云端账号**，但「关于页」仍然有意义：用户需要一个地方确认「我现在
装的是哪个版本、数据放在哪里、会不会联网上传」。本 fork 的词库与配置
全部落在本机用户数据目录，这条隐私承诺必须**在产品界面上可核对**，而不是
只写在文档里。

此时暴露三条硬约束：

1. **P2 红线**：TSF 侧与面板点击回调内禁止阻塞 I/O。版本号若在窗口显示
   或按钮点击时现场读盘，就是阻塞 I/O。
2. **P5**：用户可见文案必须是简体中文。
3. **版本号 / 产品名不得硬编码第二份**：仓内已有「版本号来自 PE 版本资源」
   的既有口径（`AGENTS.md §4.3` 用 `.VersionInfo.FileVersion` 做门禁核验），
   关于页若另抄一份字面量，就是第二个真相源。

另外，**L175 已经在这个位置埋过雷**：rc 的字符串表里 `FileVersion` 曾因缺
`STRZ()` 被写成空串 ⇒ 单字段读取会静默拿到空值。版本读取必须有回退链。

## Decision

**一、槽位语义定案（4 槽保留，不摘除）**

- **槽 0（Schema）→ 切换到下一个输入方案。**
  Rime 会话宿主就在 `WeaselServer` 进程内，因此服务端直接对**活动会话**
  调 `rime_api->select_schema()` 即可，不走 IPC。
  「当前在哪个方案、下一個是谁」的判定抽成 header-only 纯函数
  `fluxing::NextSchemaId()`（`include/FluxingSchemaCycle.h`），生产代码与
  单元测试同源（constitution R7）。
- **槽 3（Account）→ 打开「关于 / 账号说明」页。**
  页面在仓内新增 `WeaselServer/AboutDialog`（进程内、modeless、原生
  caption 框 + `ModalChrome` 渐变底），**不新建 exe、不用 MessageBox**
  （MessageBox 会阻塞服务端 UI 线程）。
- 槽 1 / 2 语义不变。

**二、版本与产品名的唯一真相源 = 宿主 exe 的 PE 版本资源**

- 取值路径：`\StringFileInfo\<lang><cp>\ProductName` /
  `ProductVersion`，语言块按 zh-CN > zh-TW > en-US > en-GB 显式排序
  （rc 里同时存在多块，取第一块会在非中文系统上显示错语种）。
- 回退链：`ProductVersion` → `FileVersion` → `VS_FIXEDFILEINFO`
  （固定版本信息，恒存在）—— 为 L175 的空串陷阱兜底。
- **启动期读一次并缓存**：`AboutDialog::Initialize()` 在服务端构造函数里
  调用一次，把产品名、版本号、用户数据目录全部读进内存。**窗口的显示、
  绘制与按钮点击路径零 I/O**（守 P2）。
- 读不到时才回退到 `Fluxing` / `未知`；这不是第二份版本号，只是没有版本
  时的占位。

**三、槽位布局的单一事实源**

新增 public `QuickPanelDialog::SlotRect(index, …)` 返回槽位的**物理像素**
矩形。`HitTest` 与单元测试都从这里取值 —— 测试不再复制一份布局公式
（复制即漂移）。点击路由同样收敛到 public
`QuickPanelDialog::DispatchSlotClick(index)`，两处点击分支（拖拽 fall-through
与原地抬起）都走它，避免「两个分支各写一遍槽位语义」的漂移。

**四、「打开数据目录」= 本地 `explore`**

关于页提供「打开数据目录」按钮，调用
`ShellExecuteW(nullptr, L"explore", dir, …)`。本地资源管理器、**不联网、
不等待**。面板不新增任何默认联网行为。

## 被否决的替代方案

| 替代方案 | 否决理由 |
| --- | --- |
| 槽 0 继续拉起 `WeaselDeployer /hotkey` | 全仓唯一调用点即死代码；「拉起别的进程的窗口」不是确定的用户可见效果，违例 spec 099 P0-3 验收 |
| 槽 0 改为「切换中/英文」 | 裸 Shift 已有该语义（ADR 0010），再做一处会造成两套语义；且中英切换不是「方案」槽该干的事 |
| 槽 3 摘除，`kButtonCount` 改 3 | 用户 2026-11-04 定稿「槽位保留」；且 4 槽布局已进设计稿与像素级回归基线，摘除会连带动 DPI 验收期望值 |
| 槽 3 用 `MessageBox` | 阻塞服务端 UI 线程（P2）；文案排版不可控，装不下「数据目录」这类长路径 |
| 槽 3 新建独立 exe | 多一个进程、多一条 IPC 通道 ⇒ 触发 IPC 四边同步；本页只有静态文案 + 一个本地 explore，无此必要 |
| 版本号在窗口显示时现场读 PE | 违反 P2（显示期零 I/O），且每次显示都做磁盘 I/O |
| 硬编码版本号字面量 | 第二个真相源，与既有 `.VersionInfo` 口径漂移；也违「版本不得硬编码第二处」 |

## Consequences

- ✅ 4 个可见槽位**全部**有确定的用户可见效果，spec 099 P0-3 验收条款
  成立。
- ✅ 「本机存储、不上传」的隐私承诺有了**可核对的产品界面出口**，不再只
  是文档承诺。
- ✅ 版本号仍然只有一个来源（PE 版本资源），并且比过去多了一条回退链，
  L175 的空串陷阱不会再复现。
- ✅ 关于页不联网、不等待、不阻塞 ⇒ P2 红线守住；`WeaselIPCData.h` **未
  改动** ⇒ 不触发 IPC 四边同步。
- ✅ 顺带修掉一个**槽位点击被随机吞掉**的既有缺陷：面板判定「拖拽 vs 点击」
  时读真实光标位置，旧代码在 `GetCursorPos` 失败（无输入设备 / 非交互
  window station / RDP 断开）时读到的是**未初始化内存**，位移是垃圾值 ⇒
  点击被误判成拖拽而不派发回调。新代码对失败路径兜底（取不到光标 ⇒ 视作
  「没动」），详见 lessons-learned **L178**。
- ✅ 槽位布局有了单一事实源，后续 P0-4（状态回显）/ P0-5（键盘可达性 /
  tooltip）可直接复用 `SlotRect`。
- ⚠️ `select_schema()` 作用于**活动会话**是 librime 的 per-session 语义：
  面板被别的窗口接管时，切换效果未必落在用户当前光标处。这条**只能靠装机
  手点复验**，本会话无法端到端验证。
- ⚠️ 关于页的**像素级版式**（420×300 客户区、圆角 12）没有视觉基准 ——
  它是自研版式，不追随任何第三方设计稿（合规红线：不复用第三方资源与
  文案）。装机时需人眼确认一次。
- ⚠️ `AboutDialog::Initialize()` 在服务端构造函数里同步读一次 PE 版本资源
  与用户数据目录。构造函数在启动路径上，**这一次**同步 I/O 是可接受的
  （不在 TSF 回调内，也不在面板点击路径内），但若将来把它挪到别的线程，
  必须重读 P2 约束。
- ↩️ 可逆：槽位语义、页面版式、版本读取策略都可以单独回退，不涉及线格式
  与协议，回退不需要同步改前端或部署端。
