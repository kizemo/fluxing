| 项 | 结论 |
|---|---|
| 首版通道 | **Cloudflare Email Service**（Workers `send_email` 绑定） |
| 为什么不是外部服务 | 同厂商、**不需要第三方账号与 API key**、不需要额外合规审查 ⇒ 天然落在 T101 边界内 |

## 2. Cloudflare Email Service 的能力边界（一手）

**来源**：`https://developers.cloudflare.com/email-service/api/send-emails/workers-api/index.md`
**`dateModified`**：2026-10-30

| 维度 | 事实 |
|---|---|
| 接入形态 | Workers 绑定名为 `send_email`；调用 `send(message): Promise<EmailSendResult>` |
| 旧接口 | 另有 `EmailMessage` 旧 API，文档标注为兼容保留 |
| 收件人上限 | **50 个**（`to` + `cc` + `bcc` 合计） |
| 附件上限 | **32 个** |
| 单封总大小 | **≤ 25 MiB** |
| 备选通道 | 除 Workers 绑定外，另提供 **REST API** 与 **SMTP** 两条发送路径 |

**错误码集合（原文为错误码表，节选与本次选型相关的）**：

| 错误码 | 含义（译文） | 对验证码流程的意义 |
|---|---|---|
| `E_SENDER_NOT_VERIFIED` | 发件人未验证 | ⇒ **发件域必须先完成 onboarding**，否则一封都发不出（§6 未验证项） |
| `E_RATE_LIMIT_EXCEEDED` | 触发速率限制 | 重发按钮必须有客户端节流，不能靠服务端 429 兜 |
| `E_DAILY_LIMIT_EXCEEDED` | 触发每日额度上限 | 与 §3 的 3,000 封/月是两个不同的闸 |
| `E_ACCOUNT_SUSPENDED` | 账号被停用 | 需要监控告警，不是用户侧错误 |
| `E_RECIPIENT_SUPPRESSED` | 收件人在抑制名单内 | **不得**把「发不出去」显示成「验证码错误」 |
| `E_CONTENT_TOO_LARGE` | 内容超限 | 25 MiB 上限，验证码邮件远达不到 |
| `E_DELIVERY_FAILED` | 投递失败 | 对用户 = 「邮件发送失败，请重试或换邮箱」 |

## 3. 定价与配额（一手）

**来源**：`https://developers.cloudflare.com/email-service/platform/pricing/index.md`
**`dateModified`**：2026-06-09

| 项 | 事实 |
|---|---|
| **Workers Free 计划** | **出站发送不可用**（没有出站邮件能力） |
| **Workers Paid 计划** | 每月含 **3,000 封**；超出部分 **$0.35 / 1,000 封** |
| 入境（Email Routing 收信） | 两档计划均**无限量** |
| 发往「已验证目标地址」 | **免费，且不占用额度** |
| 在 API 边界被拒（含被抑制名单拦下） | **不计入额度** |
| 硬退信（hard bounce） | **计入额度** |
| Email Routing 的 Workers 调用 | 按 Workers 定价**另计** |

### 3.1 成本换算（验证码场景）

假设每个账号：首次发送 1 封 + 最多 2 次重发 = **≤ 3 封**。

| 月新增注册 | 邮件量 | Cloudflare 侧成本 |
|---|---|---|
| 300 | 900 封 | **$0**（含在 Paid 计划额度内） |
| 1,000 | 3,000 封 | **$0**（正好用满） |
| 3,000 | 9,000 封 | 超出 6,000 封 ⇒ **≈ $2.10** |
| 10,000 | 30,000 封 | 超出 27,000 封 ⇒ **≈ $9.45** |

**结论**：只要月新增注册 ≤ 1,000，邮件成本为 **0**（不含 Workers Paid 计划本身的月费，见 §6）。

### 3.2 两个易混淆的闸

- **每日额度**（`E_DAILY_LIMIT_EXCEEDED`）：单位是「天」，被打到会当天全废。
- **每月 3,000 封**：单位是「月」，超出后按量计费（不是硬停）。
两者**不是同一个限制**，客户端文案不应合并成一句「今日额度已满」。

## 5. 账号状态机约束（写给 Y/Z 批次）

由 `plan.md` §4.4 + 本报告共同确定，**不接受简化**：

| 状态 | 能否登录 | 能否读写同步数据 | 能否发重发验证码 |
|---|---|---|---|
| `pending`（已注册未验证） | 否（或只能进验证页） | **否** | 是（受节流） |
| `verified` | 是 | 是 | 否（已无需） |
| `suppressed`（邮件进抑制名单） | 是（若已 verified） | 是 | **否** —— 必须提示换邮箱，不能反复重试 |

**硬规则**：`pending` 状态下**任何**写入同步数据的请求必须被服务端拒绝，且客户端不得把本地数据标记为「已同步」。

## 7. 与 T103 的交叉

- T103（`endpoint-reachability.md`）实测 `*.workers.dev` 在境内**被 DNS 污染且 443 不可达**。本文选定的通道运行在**同一个 Cloudflare Worker 运行时**里，因此**同一条红线**：发送验证码的 API 也必须走 `https://api.<自有域名>`，**不能**把 `workers.dev` 写进任何默认值。
- 两条结论互相独立，但指向同一个约束 ⇒ 在 Y 批次实现时按「CF 运行时 + 自有域名」一次性对齐。
