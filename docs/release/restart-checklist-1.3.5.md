# 重启后测试清单 · Fluxing 1.3.5（批次 AW）

> 用途：用户方便时**注销 / 重启**后，按本清单逐条验收。
> 前置：`WeaselServer.exe` 是 **PPL**（Protected Process Light）进程 ⇒ 旧映像会一直活到注销/重启；
> TSF 侧的 `weasel.dll` 也只在重启后才会换成新码 ⇒ **必须重启，否则以下结论不可信**。

---

## 0. 重启后第一件事（30 秒自检）

1. 打开「设置 → 应用 → 已安装的应用」，确认 **Fluxing 版本 = 1.3.5**。
2. 随便打开一个输入窗口（记事本即可），切到火流猩输入法，**正常打几个字**。
   - 期望：候选窗正常弹出、候选可选、上屏正常。
   - 若出现「打字没反应 / 候选窗不出现」⇒ 立刻停下并告知（这会指向会话复活路径的缺陷）。
3. 任务栏托盘右键 → 确认有「账号与同步」入口。

---

## A. 本批两个缺陷（**必须过**）

### A1 · 开启输入法不再阻塞云同步 ★核心

| 步骤 | 操作 | 期望 |
| --- | --- | --- |
| A1-1 | 打开记事本 → 切到火流猩输入法（**一个字都不打**）→ 右键托盘 →「账号与同步」→ 点「立即同步」 | 状态行显示**同步中 / 同步成功**，**不再**出现「你正在输入，本轮已跳过用户词典同步，稍后会自动重试。」 |
| A1-2 | 保持输入法激活、仍然不打字，等 1 分钟后再点一次「立即同步」 | 仍然能同步成功（证明不是偶然放行一次） |
| A1-3 | **反向判据**：在输入窗口里连续打字（例如随便敲 10 个字，**停在组合中不选词**）→ 立刻点「立即同步」 | 期望**仍然**提示「你正在输入…」⇒ 说明闸门没被彻底拆掉（这是对的，别误判成回归） |
| A1-4 | 打完字后**停手 15 秒以上**，再点「立即同步」 | 期望同步成功（空闲宽限期 = 10 秒） |
| A1-5 | 打字后停手约 5 秒就点「立即同步」 | 期望**仍**提示「你正在输入…」（未过空闲宽限期） |

> 判读口径：**A1-1 / A1-2 / A1-4 必须成功**；A1-3 / A1-5 必须仍被拦。
> 只报「跳过」不算通过；报「同步成功」才算。

### A2 · 「账号与同步」窗口第二次进入后可以关闭

| 步骤 | 操作 | 期望 |
| --- | --- | --- |
| A2-1 | 托盘右键 →「账号与同步」⇒ 窗口打开（显示已登录态） | 窗口正常显示账号信息 |
| A2-2 | 点右上角 **关闭** | 窗口消失 |
| A2-3 | **再次**点「账号与同步」 | 窗口**再次正常打开**（不是白板、不是半死窗） |
| A2-4 | 点右上角 **关闭** | ★**窗口真的关掉**（这是本批修的主缺陷） |
| A2-5 | 第三次进入 → 不关闭 → 在窗口内切到「设备与云数据」子页 → 再切回「账号」 | 切换正常；切回后点关闭**仍能关掉** |
| A2-6 | 第二次进入后，按 **Esc** / **Alt+F4** | 也能正常关闭（统一走 WM_CLOSE 路径） |

> 判读口径：A2-4 是**唯一**的关键判据；其余为回归防护。

## B. 批次 AV 遗留核心判据（换口令后自动全量重推）

> 前提：已用 `kizemo@163.com`（或你自己的账号）登录，且**旧版本曾经上传过词条**。

| 步骤 | 操作 | 期望 |
| --- | --- | --- |
| B-1 | 账号页 →「忘记口令」→ 收验证码 → 重置为**新口令** → 用新口令登录 | 登录成功；账号页状态行提示「加密密钥已变化，已重置本地同步状态并全量重推。」（或等义中文） |
| B-2 | 重置后**不手动点同步**，等 1～2 分钟 | 自动发起一轮全量重推；状态行出现「已推送 / 同步成功」 |
| B-3 | 本地新造一个词条（例如随便打几个生僻字让它进个人词库） | 该词条能在**另一台设备**登录同一账号后看到 ⇒ 说明全量重推真的把本地整库传上去了 |
| B-4 | 在账号页点「清空云端数据」 | 提示确认 → 确认后本地同步状态被重置 → 下一轮自动把整库重新推上去（不会「本地显示已同步、云端却没有」） |

## C. 双机验收（需要**第二台设备**；`CloudCredentialStore` 是 Windows 用户级全局单例 ⇒ 两套 Profile 目录不够）

| # | 判据 | 期望 |
| --- | --- | --- |
| C-1 | 设备 A 登录 → 造词条 → 同步 | A 本地有、云端有 |
| C-2 | 设备 B 登录**同一账号** → 拉取 | B 能看到 A 的词条 |
| C-3 | B 上再改一个词条 → 同步 | 两端一致（合并生效） |
| C-4 | A 再拉取 | A 能看到 B 的改动 |
| C-5 | 断网（拔网线 / 断 Wi-Fi）→ 改词条 → 恢复网络 | 离线期的改动在恢复后自动补传 |
| C-6 | 设备 B **退出登录** → A 仍可正常同步 | 不因单设备退出而阻塞 |
| C-7 | 两台设备**同时**改同一个词 | 不产生重复条目 / 不互相覆盖成乱码 |

## D. 性能对照（两组，各测 3 次取中位数）

| 项 | 测法 | 期望 |
| --- | --- | --- |
| D-1 | 输入延迟：同一台机器、同一窗口、同样的 30 字句子，分别在 **1.3.4** 与 **1.3.5** 下各输入 3 次 | 1.3.5 **不得**明显变慢（本批放宽了闸门 ⇒ 维护更频繁 ⇒ 这是本批最需要盯的性能项） |
| D-2 | 内存：任务管理器观察 `WeaselServer.exe` 的私有工作集，闲置 5 分钟后读数 | 与 1.3.4 同量级（ADR 0030 的 40 MB「无会话稳态」基线仅作参考，**口径不同**） |
| D-3 | CPU：闲置时 `WeaselServer.exe` 的 CPU 占用 | 按 ADR 0060 口径「占单核」读，< 0.1 % 为合格；采样窗口 ≥ 16 秒 |

每条只要一句话即可，例如：

```
A1-1 通过 / A1-3 仍提示跳过 / A2-4 关不掉 / B-1 登录成功但没有自动重推 …
```

失败的条目请附**截图**（尤其是账号页状态行那一行）。若 A2 仍关不掉，请同时说明：
**第二次进入后窗口是「完全画不出来」还是「画得出来但按钮没反应」**。

## F. 本批已知的「不是缺陷」现象（别误报）

1. **打字后立刻同步会提示「你正在输入」** —— 这是**故意**的（ADR 0065 决策 1/3：未上屏组合串与刚打完字都要保护输入窗口）。
2. **重置口令后云端旧数据还在且不可解** —— 这是**方案 C 的已知代价**（用户需显式点「清空云端数据」才彻底清掉），不是 bug。
3. **输入法刚激活、还没打字时，云同步可能已经跑过一轮了** —— 状态行显示的是最近一轮的结果，不是实时排队状态。
