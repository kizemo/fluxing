一、证明方法
--------------------------------------------------------------------------------
门禁最大的风险不是「漏检」,而是「检查恒绿」——看起来在跑,其实永远返回通过。
本次用**变异测试**证明 L1 门禁真的有齿:

  1. 把门禁要读的 7 个文件复制到仓库外的临时目录(不让任何变异污染工作区):
         include\FluxingPanelDpi.h
         include\FluxingPanelStatus.h
         include\FluxingPanelKeyboard.h
         include\FluxingPanelTooltip.h
         include\WeaselIPCData.h
         WeaselServer\QuickPanelDialog.cpp
         WeaselServer\WeaselServerApp.cpp

  2. 门禁用 -Root <临时目录> 读取副本 ⇒ 同一份检查实现被指向不同源码树。

  3. 五轮运行:
         CONTROL   未变异的副本          —— 必须绿(exit=0),否则无法区分「有齿」和「坏掉」
         MUTANT M1 删掉 WM_TIMER 里的 RefreshInputState() 调用 —— 必须红(exit≠0)
         MUTANT M2 把共享 DPI 调用换成手抄的缩放公式        —— 必须红(exit≠0)
         MUTANT M3 让 FluxingPanelStatus.h 引入 WeaselIPCData.h —— 必须红(exit≠0)
         ORIGINAL  原仓库工作树          —— 必须绿(exit=0)

二、变异体清单
--------------------------------------------------------------------------------
M1  变异点 : WeaselServer\QuickPanelDialog.cpp
    位置   : WM_TIMER(id=2) 分支里的 RefreshInputState();
    做法   : 该调用整行替换为注释
    期望翻红: C1 state-echo-refresh
              (状态回显的刷新点从 2 处掉到 1 处 —— 轮询节拍没了,状态会停在注入那一瞬)

M2  变异点 : WeaselServer\QuickPanelDialog.cpp
    位置   : 局部包装 ScaleLogicalByDpi(int, UINT)
    做法   : return fluxing::panel_dpi::ScaleLogicalByDpi(logical, (int)dpi);
             换成 return (logical * (int)dpi + 48) / 96;   ← 自己抄了一份真相源
    期望翻红: B2 dpi-single-source
              (共享缩放实现不再被调用,且源码里出现手抄公式的指纹)

M3  变异点 : include\FluxingPanelStatus.h
    位置   : 文件头
    做法   : 插入 #include "WeaselIPCData.h"
    期望翻红: H1 ipc-boundary-intact
              (spec 099 P0-4/P0-5 不得改动 IPC 协议边界 —— 纯逻辑 header 不该知道 IPC 长什么样)

2. F1(display-path-zero-io)检查里,WeaselServer\QuickPanelDialog.cpp 存在 3 处
   CreateFileW(v0.19.0.10 起就有的诊断 dump),全部位于
   `GetEnvironmentVariableW(L"FLUXING_QP_DIAG_DUMP", ...)` 门控的块内 ——
   即「显式设了环境变量才会跑」的诊断路径,不在正常显示路径上。
   门禁把这块**按 env 门控识别出来并排除**,并在 PASS 明细里显式报出排除了几处。
   门控一旦被摘掉(诊断 dump 落回显示路径),F1 会立刻翻红。

3. 门禁脚本本身用 UTF-8 + BOM + CRLF;期望的中文文案由**码点构造**
   (见脚本内 $script:RequiredZh),不依赖脚本文件自身的编码 ——
   即使 BOM 被编辑器抹掉,检查结果也不变。
