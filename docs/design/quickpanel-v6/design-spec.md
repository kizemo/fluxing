## 1. 产品与场景

**产品**：Fluxing / 火流猩输入法（WeaselServer/小狼毫 fork）的**快捷设置栏**。
它是常驻（或唤出即现）的**微型工具条**，贴在桌面右下角，四个键帽从左到右：

| 视觉位 | 功能 | 现实现图形（viewBox 30×30 内的实际描线几何） |
|---|---|---|
| 0 | 切换到下一个输入方案 | 双向箭头：上行 (5,11)→(23,11) + 箭头头 (19,8)(23,11)(19,14)；下行 (25,19)→(7,19) + 头 (11,16)(7,19)(11,22) |
| 1 | 中英文切换 | 汉字单字「中」（中文态）/「英」（英文态），字号随缩放系数走 |
| 2 | 全角/半角切换 | 对角线布局：右上**空心环**（全角）或**实心点**（半角）+ 左下逗号尾「，」 |
| 3 | 用户短语（自定义短语） | 对话气泡：圆角矩形 (5,5)-(25,20) 圆角 6 + 尾巴 (10,20)(8,25)(13,20) + 两条文本横线 (9,10)-(21,10) 与 (9,14)-(18,14) |

左侧是**品牌区**：火流猩红猿头 logo（PNG，`docs/design/fluxing-logo.png`，
装机后从用户数据目录读取，WIC 解码成不透明位图贴到面板底色上）。

**使用场景**：用户在写文档/聊天时，右手在键盘上，眼睛偶尔瞟一眼右下角，
**0.3 秒内**要确认「我现在是中文还是英文 / 全角还是半角」，偶尔要点「换方案」
或「翻自定义短语」。它**不是**一个需要沉浸阅读的面板，而是**一眼扫过就要读懂**的状态灯。

**物理尺寸**：逻辑 155 × 32 px（100% DPI）。150% ⇒ 233×48，200% ⇒ 310×64。
**这是本设计最大的约束**：155×32 的画布上要塞下 logo + 4 个键帽 + 状态表达，
还要求在 200% 缩放下比例完全同比。

**当前实现的问题（用户原话「设置栏缺乏美感」）**：
1. 面板本体是一坨**浅蓝渐变**（`RGB(200,225,250)` → `RGB(155,195,240)`）圆角块，
   描边是浅灰蓝；颜色既不属于品牌（品牌是橙 `#FF5F31` + 紫 `#9B51E0`），
   也不像系统控件（Windows 11 强调色是蓝但没这么脏的渐变）——**两头不靠**。
2. **logo 与图标语言打架**：logo 是**高饱和红色实心插画**（拟物、带高光），
   周围四个图标是**灰色细线描边**（几何、扁平）——一块面板里两套视觉语言。
3. **图标光重不均**：⇄ 双向箭头（2px 线 + 两个箭头头）视觉重量远大于
   逗号 + 小圆环（全半角槽），四个键帽并排时右半边看着「空」左半边看着「挤」。
4. **状态不可见**：中/英 与 全/半角 只靠「某一个键帽上换了字形」表达，
   没有底色/形状上的状态区隔 ⇒ 扫一眼看不出当前是英文态还是中文态。
5. **没有键帽**：四个图标直接浮在面板底色上，没有可点击区域的心智模型
   （鼠标移上去时才有橙色反馈，但**默认态没有落点**）。
6. 品牌红猿头 + 浅蓝底 = 撞色且廉价。

## 2. 目标受众与情感基调

- **受众**：每天用输入法超过 4 小时的办公/写作用户（专业文字工作者、
  程序员、翻译），对输入法 UI 的「廉价感」敏感，审美参照是 macOS / Arc /
  Linear 这类工具型软件，不是消费类 App。
- **基调**：**克制、精确、安静**。面板要像一把放在桌面的**精密小工具**，
  不是一块漂浮的糖果。信息密度高但噪点低。
- **一句话**：「一个 155×32 的胶囊，四个字讲清楚我现在处于什么输入状态」。

---

## 3. 核心信息（设计必须让人一眼读出）

1. **我现在是中文还是英文**（最重要，占一半注意力）。
2. **我现在是全角还是半角**（次重要）。
3. 另外两个键是**动作**（换方案 / 翻短语），不需要状态，只需要在被指向时清晰。

因此视觉权重应当是：**状态类键 > 动作类键**；**品牌区最安静**（不该抢注意力）。

---

## 4. 情感基调与气质关键词

安静 / 精确 / 半透明 / 有呼吸感 / 一眼可辨 / 不吵。

**明确禁止**：紫色渐变、emoji、彩色左边框卡片、发光霓虹、拟物金属、
大面积彩虹渐变、每个图标配一个圆角白底「贴纸」。

---

## 5. 输出格式与尺寸（硬约束，三方向必须统一）

- **单文件 HTML**（CSS + 内联 SVG，不引外部字体/图片文件）。
- **画布固定 1240 × 420 px**（三方向必须同尺寸，否则无法横向对比）。
- **logo 必须 base64 内嵌**：源文件 `F:\soft\00selfmade\rime_claude\docs\design\fluxing-logo.png`
  （若该文件不可读，用同目录 `fluxing-logo_small.png`）。禁止用外链路径，
  禁止用 CSS 色块/手绘 SVG 冒充 logo。
- **图标必须用内联 SVG 复刻上表的真实几何**（viewBox `0 0 30 30`），
  不得换成 emoji 或第三方图标字体；线宽用 `stroke-width="2"`（与 GDI 的
  `ScaleStroke(2, scale)` 口径一致）。
- **画布内容布局（三方向一致，便于对比）**：
  - 上排：**3× 放大**的面板（465×96）置于一块**柔和的桌面壁纸色块**上
    （用来判断半透明/投影/描边在真实背景上的表现），
    右侧并排三个状态变体：默认 / hover 第 2 键 / 中文态（英文态对比）。
  - 下排：**1× 真实尺寸**（155×32，标尺线标注）与 **2×**（310×64）各一，
    并列出该方向用到的色值表（hex）与「哪几处是 GDI 可实现的」。
- 所有文字用简体中文。

## 6. 已知约束（GDI 可实现性 —— 最重要的现实约束）

最终形态是 **Win32 GDI 自绘**（32-bit BGRA DIB + `UpdateLayeredWindow`），
**没有 CSS、没有 D2D、没有 GDI+、没有 blur/backdrop-filter**。
所以设计里出现的每一处效果都必须能落到下面这些手段之一：

| 可用手段 | 说明 |
|---|---|
| 纯色 / 线性渐变填充 | `CreateSolidBrush` + `GradientFill` |
| 圆角矩形（任意半径） | `RoundRect` |
| 抗锯齿描边 | `Arc`/`Ellipse`/`LineTo` 描边由 GDI 自行处理 |
| 逐像素 alpha（透明度） | 直接写 DIB 的 alpha 通道 |
| 软投影 | 多层不同 alpha 的圆角矩形叠加（可行） |
| 文字 | `CreateFontW` + `DrawTextW`（中文可用宋体/微软雅黑） |
| 位图 | logo（PNG，WIC 解码） |

**不可用**：高斯模糊毛玻璃、真实 backdrop 采样、box-shadow 的连续衰减、
CSS 渐变网格、SVG 滤镜、任何非 GDI 的阴影。
⇒ **任何依赖 backdrop-filter 的「毛玻璃」方案在实现阶段要退化为
「半透明纯色 + 细描边 + 分层投影」**，设计稿里请按后者来画，不要画真毛玻璃。

## 7. form 推导五问（设计必须回答）

1. **叙事角色**：它是**状态灯 + 动作条**，不是导航、不是仪表盘、不是菜单。
2. **观众距离**：40–60 cm（显示器前的桌面工具条），所以关键信息（当前态）
   必须在 155×32 的物理尺寸上**不放大也读得出**。
3. **视觉温度**：**冷静偏暖**（不要纯冷灰，要有一点纸/石的暖度），
   品牌橙只用于「当前态强调」和「hover」，不用于大面积铺色。
4. **容量估算**：155×32 里，品牌区 26 宽 + 4 个键帽 × 28 宽 + 间隙 ⇒
   每个键帽只有 28×28，**放不下图标 + 文字标签**（32 高，图标 17 + 文字 11
   勉强但会挤）。⇒ 状态表达必须靠**图标形状/底色**，不能靠文字标签
   （除非你论证了可行的紧凑排版）。
5. **视觉母题**：这内容独有的母题是「**四种输入态在一枚胶囊里并列**」——
   天然对应**胶囊 / 轨道 / 分段**这几种形态（而非卡片、栅格、列表）。
   请从「胶囊里并置的状态轨道」这一母题出发推导形式，
   并在交付里用一句话说明「form 来自内容的哪里」。

## 8. 图片需求判定（Phase 3.5）

- 本设计**不需要**内容型图片（工具条不是内容型）。
- **唯一的品牌资产是 logo PNG**（已给路径，必须 base64 内嵌、必须真实使用）。
- 其余一切用矢量/纯色表达，**不要**编造装饰性插画。
