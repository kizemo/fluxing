QuickPanel 5 版设计对比 · Fluxing v0.19

约束条件(来自 L67-L69 教训):新设计必须避开 GDI+ Bitmap(IStream*) 生命周期雷区。
本对比展示 5 种视觉方案,每种都明确标注实现技术栈与避雷路径。

为什么 QuickPanel 之前一直在崩

v0.18.29.0 - v0.18.41.3 共 4 个版本都在用 GDI+ Bitmap(IStream*) 渲染 logo。 GDI+ 内部为 lazy pixel-decode 缓存 IStream 指针;在 stream->Release() 后, 首次 paint 触发 vtable UAF → heap corruption → 后续任意堆操作(NtSetValueKey / RtlDeleteTimer) 检测损坏 → STATUS_HEAP_CORRUPTION → WeaselServer.exe 退出 → TSF pipe 断开 → 用户无法输入中文。

5 版全部用 Direct2D 或原生 GDI,完全不用 GDI+ Bitmap/IStream。

评审建议

v4 (Pure Icon Row / GDI) 作为 v0.19.0.0 ship 切片 优先:
- 完全脱离 GDI+ Bitmap/IStream 雷区,L67/L68/L69 历史问题零概率复发
- 实现只需 Win32 GDI + WM_PAINT,~150 行 C++,无 Direct2D 依赖
- 编译产物小、运行稳定、跨 Win 10/11 视觉一致
v1 / v3 / v5 是 v0.19.1+ 设计升级 备选,v2 在中文标签需求更强时考虑。
