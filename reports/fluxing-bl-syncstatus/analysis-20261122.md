## 为什么这足以判定「续期路径生效」

1. **失败阶段前移了**：错误从「服务端 401 的中文原因」变成「本地写回阶段的中文原因」。
   按 `SyncOnce` 的执行顺序（`WeaselServer/Cloud/CloudSyncService.cpp`）：
   导出/解析本地快照 → HLC 分配 → **拉取（网络，:1000-1042）** → 合并 → **写回（:1048-1076）** → 推送（:1113-1143），
   写回在拉取之后 ⇒ 本轮**网络阶段已走通**，鉴权没有再拦下这一轮。
2. **排除「别的路径先续了期」**：BK 那两轮（修复前）在同一账号、同一过期令牌下**正是卡在 401**；
   若存在其它自动续期路径，BK 当时就不该报 401。修复后能推进 ⇒ 唯一新增的路径就是 BL 注入的续期回调。
3. **口径声明（推断，非日志直证）**：BL 的修复**没有加日志行**（`CloudSyncService.cpp:654-691` 只有注释与分支），
   凭据存在 Windows Credential Manager（`CredWriteW`，`CloudCredentialStore.cpp:210`）⇒ **拿不到「令牌被改写」的文件级物证**。
   上述结论是由「阶段前移 + BK 同期对照」推出的**强推断**，不是日志直证。
   若要把它升级为直证，需在续期分支加一条**无条件打印**的日志行（见 BM 的可选项 A）。

## 新缺陷（BM 候选，本批未修）

### 现象
同步轮次在**写回阶段**失败，1017 报「词典条目载荷格式不正确。」。

### 根因链（已逐环坐实）
1. `CloudUserDictIo.cpp:145` —— 全仓唯一产生该文案的点：
   `BuildUserDictSnapshots` 里 `SplitDictPayload(rows[i].payload)` 失败（payload 里没有制表符）。
2. `BuildUserDictSnapshots` 在 `WeaselServer/Cloud` 内**只有一个调用点**：`CloudSyncService.cpp:1070`
   （合并后的写回）⇒ 失败行属于**合并集**。
3. **本地行已被证伪为元凶**：本轮导出的快照
   `D:\Program Files\fluxing\user1\fluxing\sync\adbd9f3b-…\rime_ice.userdb.txt`
   共 **94 607 行**：数据行 **94 601 行全部 3 列**，另 6 行非 3 列**全是 `#` 元信息/头行**
   （`# Rime user dictionary`、`#@/db_name`、`#@/db_type`、`#@/rime_version`、`#@/tick`）
   ⇒ 无 2 列数据行 ⇒ 本地 payload 均含制表符（`SplitDictRow` 只有 2 列时才不含，`CloudUserDictIo.cpp:268-270`）。
   （本报告早期假设「本地有 1 行 2 列数据」——**已证伪**，不要沿用。）
4. `changed == true` 才会走写回 ⇒ **云端确实有条目**（远端为空则 merged == local、不会写回）。
5. 合并集里的远端条目 payload 直接来自 `OpenItems`（`CloudSyncService.cpp:1268-1298`）：
   解密/拆封/MAC 自校验通过即可，**不校验 payload 形态**
   ⇒ 一条 payload 无制表符的**云端旧条目**被 `OpenItemsTolerant` 放进合并集，
   在写回阶段炸掉整轮。
   （推论：该条目是**早于本次修复、某次上传**时写进去的脏数据 —— 本机当前快照已无 2 列行。）

### 连带隐患（同源，BM 一并处理）
- `JoinDictRow`（`CloudUserDictIo.cpp:235-250`）在 payload 形态非法时**返回空串**，
  调用方 `BuildUserDictSnapshots` 会把这一行**写成空行**（`out->append(JoinDictRow(...))`）⇒ 静默丢数据。
- 现状口径下，**一条脏云端条目即可永久卡死每一轮同步**（每轮都在同一处炸）。

### 推荐修法（BM，沿用仓内既有「跳过不可用条目」先例）
- **主修**：在开箱侧（`OpenItems` / `OpenItemsTolerant`）对**用户词典类**条目做与 `SplitDictPayload`
  一致的形态校验；形态不合法的条目按「不可用」计入 `undecryptable` 计数并跳过，
  **不再让单条脏条目毒化整轮合并**（先例：旧密钥加密的行本来就按 `undecryptable` 跳过，
  `CloudSyncService.h:189-198`）。
- **配套**：`JoinDictRow` 遇形态非法改为**报错**而非返回空串（消除静默空行丢数据）。
- **可选 A**：在续期分支加一条**无条件打印**的日志行 ⇒ 把本报告第 3 点的「强推断」升级为直证。
- **配套测试**：`test/TestFluxingCloud` 增加「云端混入一条 payload 无制表符的条目 ⇒ 该轮**不失败**、
  该条被跳过计数」用例（BL 组已 653 断言全绿，基线须只增不减）。
