# Patterns：定制模式库

> 每个模式写成「何时用 / 怎么做 / 代价」。模式 = 可复用的做法，不是片段。

## P1 · 局部覆盖，继承其余

**何时用**：只想改一个方案的一个设置，不想抄整份配置。

**怎么做**：建 `<方案代号>.custom.yaml`，写 `patch:` 指向那个节点。编译器自动把该方案的
源配置作为基底，你的补靪叠加在上面。

**代价**：补丁之间会互相影响——同一节点上多个补靪按加载顺序叠加，顺序由文件加载顺序决定，
不是书写顺序。

## P2 · 重述 include 再覆盖（librime T1）

**何时用**：要覆盖的节点在源 schema 里是 `__include: default:/xxx` 引入的
（如 `punctuator/half_shape`、`key_binder`）。

**怎么做**：

```yaml
patch:
  punctuator/half_shape:
    __include: default:/punctuator/half_shape
    '/': '、'
```

**代价**：多一行样板；而且**如果源节点本来不是 include 引入的，写上这行反而会清空内容**。
所以先看源 schema。

## P3 · 追加而非替换（`/+`）

**何时用**：要往 `key_binder/bindings` 这类已有列表里加条目，不影响别人的绑定。

**怎么做**：`key_binder/bindings/+:` + 列表项。

**代价**：`/+` 是**合并**，不保证位置；想要精确位置用 `@before`/`@after`——但官方不建议。

## P4 · 开关隔离（独立开关名）

**何时用**：某方案要"固定输出简体"这类行为，且不希望污染别的方案。

**怎么做**：新起一个开关名（如 `zh_simp`），在 `switches` 里定义它，
再让 `simplifier/option_name` 指向它。

**代价**：多一个开关（方案选单里会多一项）；但换来跨方案行为干净。

## P5 · 标点两层分工

**何时用**：要改标点，尤其是 `Shift+标点`。

**怎么做**：直接按的键 → `punctuator/half_shape`（+ P2）；
`Shift+键` → `key_binder` 拦截后 `send` 字符。

**代价**：两处要维护；`key_binder` 必须排在 `punctuator` 之前的处理顺序里。

## P6 · 编码映射外挂（拼写运算）

**何时用**：要开模糊音、简拼、容错、按键纠错，或把双拼接到已有词典。

**怎么做**：在 `speller/algebra` 挂算式（模糊音/容错用 `derive`，简拼用 `abbrev`），
或用 `speller/algebra/__patch` 挂预设条目（朙月拼音的新写法）。

**代价**：算式写错不报错，只是没效果；验证要靠实际敲。

## P7 · 先造词库，再造方案（分阶段）

**何时用**：从零做一套输入方案。

**怎么做**：
1. 用现有方案 + `custom_phrase.txt` 验证交互习惯（不写任何新文件）；
2. 复用官方 dict，加自定义短语；
3. 写自己的 `*.dict.yaml`；
4. 写自己的 `*.schema.yaml`；
5. 需要时才上 Lua 扩展。

**代价**：前期慢，但每一步都能独立验证，出错时知道是哪层。

## P8 · 词典扩展包

**何时用**：要给固定音节表的方案加词，但不想重编主词典。

**怎么做**：单独构建扩展包 `*.dict.yaml` → 编成 `*.table.bin` → 方案里
`translator/packs` 列包名。

**代价**：**扩展包与主词典必须共用音节表**，librime 不做校验；
二进制包不宜脱离主词典分发。

## P9 · 快照优先的词典迁移

**何时用**：换机器、重装、备份用户习惯。

**怎么做**：用 `*.userdb.txt` 快照做**合并**（词频取较大值），
而不是导出文本码表再导入。

**代价**：快照不能人工编辑；文本码表可读但信息不全。

## P10 · 移走再部署（隔离基线）

**何时用**：怀疑问题出在自己的补靪。

**怎么做**：把 `<方案>.custom.yaml` 改名移走 → 部署 → 观察是否为发行版基线行为。

**代价**：部署一次要时间（编译大词典）。

## P11 · 一次性改一个变量

**何时用**：任何多变量改动。

**怎么做**：改一处 → 部署 → 验证 → 再改下一处。改动多时用 P10 二分。

**代价**：慢。但 Rime 的静默失效太多，一次改多处等于放弃定位。

## P12 · 用 `build/` 验收而不是源文件

**何时用**：每次改配置之后。

**怎么做**：部署后打开 `<用户文件夹>/build/<name>.schema.yaml`，确认你的值在、且邻居值没被误伤。

**代价**：一次文件读取。收益是**唯一能证明"改动确实进了运行时"的动作**。
