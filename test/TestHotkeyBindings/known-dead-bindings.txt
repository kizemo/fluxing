# Known-dead key_binder bindings in the Fluxing configuration.
#
# THIS FILE IS NOW EMPTY ON PURPOSE.
#
# The TSF front end sends the *character* a key produced, not the key
# itself (WeaselTSF/KeyEvent.cpp:51 ToUnicodeEx). librime matches a
# binding on the exact (keycode, modifier) pair
# (librime/src/rime/key_event.h:43). So a binding that names the
# unmodified key can never fire once a modifier is involved.
#
# Every entry below is a binding that the acceptance gate
# (test/TestHotkeyBindings) proved can never fire. They are listed here
# so the gate stays green for everything else and turns red the moment a
# *new* dead binding appears. Fixing them is tracked in the next phase
# development plan (see docs/agents/ and the verification report).
#
# History:
#
#   6 entries -> ADR 0009: the two redundant duplicate chords
#                (Control+Shift+9 / Control+Shift+0) were deleted from
#                output/data/default.yaml; the reachable twins
#                Control+Shift+numbersign / Control+Shift+dollar carry
#                the same function, so the duplicates are gone from the
#                shipped configuration instead of being registered here.
#
#   4 entries -> ADR 0009 / L149: the four Shift+punctuation bindings
#                were renamed to the character key names the front end
#                actually sends:
#                  Shift+apostrophe   -> Shift+quotedbl   (0x22)
#                  Shift+backslash    -> Shift+bar        (0x7C)
#                  Shift+bracketleft  -> Shift+braceleft  (0x7B)
#                  Shift+bracketright -> Shift+braceright (0x7D)
#                They fire now, so they are no longer defects.
#
# The baseline is intentionally empty. The gate must report
# known_dead=0 and dead=0, so ANY dead binding in the shipped
# configuration turns the build red instead of being absorbed here.
#
# Format:  <when> :: <accept>   [:: <send>, optional, for readability]
