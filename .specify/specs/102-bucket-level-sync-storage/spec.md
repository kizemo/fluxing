> **权威设计来源**：`docs/adr/0077-bucket-level-sync-storage-architecture.md`（下称「ADR 0077」，共 11 条决策 + 备选否决表）。

## 1. 目标

把云端的同步索引从「**一个词条一条索引记录**」改为「**一个（设备 × 桶）一条索引记录**」，词条包整体作为
**不透明密文**存放于对象存储。目的只有一个：**让索引记录的条数与词条数量解耦**，
使「首次导入 / 库存重建 / 换机」不再一次性打爆每日的存储写入额度。

- 现状问题（实测，见 ADR 0077 背景一节）：索引记录条数 ≡ 词条数 ⇒ 一次全量首导 ≈ 10.9 万条记录写入，
  而每日免费写入额度为 10 万条且**按整库合计**计算，一旦耗尽，**该库内所有账号的所有写操作一起失效**
  （包括真实用户登录）。
- 目标状态：一次全量首导的记录写入量降到「桶数量级」，与词条总数无关（改善倍数见 AC-107 的上界式）。
- **本批只做服务端**：新建桶级索引 + 两个新入口 + 写预算护栏按桶口径 + 账号数据清除扩展 + 单测与门禁。
  既有的逐条入口与逐条索引**逐字不动**，老客户端零感知。客户端改造属下一批（BR-①g）。

**为什么服务端可以先做**：新旧入口是两条并行路径（按地址分流），服务端先上线不影响任何既有用户，
可独立验收；这也是 ADR 0077「灰度」决策的唯一可行顺序（系统内没有任何版本或能力协商字段）。

## 3. 范围

**本批做**：
1. 新增「桶级索引记录」存储（每条记录描述一个「设备 × 桶」，指向对象存储里的一个桶包）。
2. 新增两个并行入口：按桶推送（写）与按桶拉取（读）。
3. 写预算护栏按桶口径新增一套判定与一个可配阈值；既有的按条口径阈值与文案保持原样。
4. 账号数据清除扩展为同时清理桶包与桶索引，且清理结果必须**可自证**。
5. 上述各项的自动化测试与门禁复现。

**本批不做**（完整清单见 `tasks.md` §8，属 BR-①g 客户端批次或另行拍板）：
- 客户端的分桶打包 / 拆包、桶级时序计算、游标侧车升版与重置。
- 桶大小与分片数的取值调参、传输时长实测落地。
- 逐条索引与老入口的退役（需另立决策记录）。
- 写预算护栏改为「整库合计口径」或按活跃账号分摊（待拍板）。
- 是否升级付费存储额度（待拍板）。

## 4. 功能需求（FR）

| 编号 | 需求 | 依据 |
|---|---|---|

| FR-103 | 必须提供按桶拉取的独立入口，按索引记录的顺序游标分页返回 | ADR 0077「灰度 / 拉取契约」 |
| FR-104 | 桶包内容对服务端必须是**不透明密文**：服务端不得解析、不得解密、不得据此比较或改写包内条目 | ADR 0077「blob 格式」+ 不变量 I8 |
| FR-105 | 桶标识必须是不透明派生值；服务端不得从桶标识推出词典名或任何明文分类 | ADR 0077「桶成员」 |
| FR-106 | 服务端必须以**桶级时序**做权威守卫：同一设备同一桶，已存时序 ≥ 上报时序 ⇒ 整桶跳过 | ADR 0077「双层守卫」 |

| FR-108 | 同一桶由不同设备推送时必须各自成行、互不覆盖（每设备独立视图，消除互相盖写） | ADR 0077「每设备独立视图」 |

| FR-110 | 拉取时发现桶包在对象存储已缺失，必须删除对应索引记录并跳过该桶，**不得因此返回 500**；响应字段集合不得因此新增 | ADR 0077「自愈粒度」+ 既有实现同构 |
| FR-111 | 必须提供按桶口径的每日写预算护栏：预计写入超限 ⇒ 整请求拒绝、返回「稍后重试」类限流错误、且**零写入**；限流错误码与提示文案必须与既有条目级护栏**逐字相同** | ADR 0077「护栏换表」 |
| FR-112 | 底层存储每日写入额度耗尽时必须返回**可解释**的容量错误与中文提示，判定必须走既有共享判据，不得出现第二处实现 | 前置批次的共享判据 |
| FR-113 | 写序必须为「先落对象、后写索引」；索引写失败必须整请求失败。允许残留无索引的孤儿对象（不可见、重试自然覆盖） | 不变量 I9 |
| FR-114 | 「删除账号全部同步数据」必须在一次调用内同时清理：词条包前缀、桶包前缀、两张索引表，并给出可自证的结果 | ADR 0077「灰度」+ 决策记录「继续承载」 |
| FR-115 | 既有逐条入口与其索引表必须**逐字不动**、语义不变，与桶级入口长期并行（退役需另立决策） | ADR 0077「灰度 / 分期」 |
| FR-116 | 全部用户可见的错误提示必须为简体中文；不得新增第二个限流错误码；错误提示不得泄露任何明文内容 | 宪法 P2 / P5 |
| FR-117 | 请求规模必须有明确上限并在超限时明确拒绝：单请求桶数上限、单桶包字节上限、单请求总体节上限，三者各自的拒绝语义必须可判定 | plan.md §5.1 |

## 7. 合规红线与不变量（本批必须遵守）

1. **端到端不变量**：服务端只见密文，不解密、不解析明文、不比较内容（ADR 0077「blob 格式」+ 不变量 I8）。
2. **条目级加密附注逐字不变**（`item_key | type | hlc_ms | hlc_counter | device`）⇒ 老密文在新协议里仍可逐条验证。
3. **桶级不做二次加密、不引入桶级随机串**：ADR 0077 已否决取证草案里的桶级二次加密方案（收益为零、风险为正）。
4. **桶级与条目级两套时序必须同时存在**：服务端权威 = 桶级，客户端逐条裁决 = 条目级；只留其一必然回退或乒乓。
5. **限流与容量错误语义单一**：429 只对应一个错误码与一条中文文案；503 容量错误只走一处共享判据。
6. **中文用户可见字符串**（宪法 P2 / P5）；对外服务地址不得使用平台默认子域（既有门禁拦截）。
7. **入库、部署、生产迁移均需用户授权**；本批文档轮不执行任何写操作。
8. **词典子模块不得入库**；未跟踪的构建产物与取证报告目录按红线不提交。
9. **单一真相源**（宪法 R7）：同一概念在 spec / plan / tasks 出现分歧时先停下比对，禁止三处各写一套口径。
