# 088 · Spec — 火流猩程序目录解析（托盘菜单「重启算法服务 / 程序文件夹」失效）

## Intent

用户在任务栏输入法图标的菜单里点「重启算法服务」「重新部署」，观察到：

- 「重新部署」**有效**（会重新编译方案、刷新配置）。
- 「重启算法服务」**点了完全没反应** —— 既没有重启，也不报错、不弹提示。
- 点「程序文件夹」同样没反应。

同时：当算法服务意外退出后，输入法**无法把它自动拉起**，用户只能自己去目录里双击可执行文件。

根因（已现场取证，见 plan.md「取证」一节）：输入法前端需要拿到「程序所在目录」才能启动算法服务，但它只认一个**本 fork 的安装器从不写入**的注册表值，于是拿到空路径后静默放弃。用户看到的现象是「点了没反应」，而不是「找不到程序」。

本 spec 引入的能力：

- 输入法前端能可靠解析出自己所在的程序目录（用户可见安装目录下的 `weasel` 子目录），无论安装器把注册表写进了 32 位还是 64 位系统视图，也无论使用的是火流猩自己的键还是旧版键。
- 解析失败时给出**简体中文**提示，而不是静默无反应。
- 算法服务不在时，输入法能把它拉起来。

## User Stories

### US1 — 重启算法服务（P1）

- **Why P1**：这是用户报障的直接入口，且当前 100% 静默失效。
- **Independent test**：在已安装的火流猩上，从输入法图标菜单点「重启算法服务」，观察算法服务进程是否重新出现。
- **Acceptance**：
  - Given 火流猩已安装且算法服务正在运行
  - When 用户点「重启算法服务」
  - Then 算法服务被重新启动（进程重启，PID 变化）
  - Given 找不到程序目录（安装损坏）
  - When 用户点「重启算法服务」
  - Then 弹出一句简体中文提示，说明找不到程序目录、需要重新安装
  - Then 不出现「点了完全没反应」的情况

### US2 — 打开程序文件夹（P2）

- **Why P2**：与 US1 同一根因，用户可感知的第二条入口。
- **Independent test**：点「程序文件夹」，观察是否打开了程序所在目录。
- **Acceptance**：
  - Given 火流猩已安装
  - When 用户点「程序文件夹」
  - Then 打开程序所在目录（与服务进程同目录）
  - Given 找不到程序目录
  - When 用户点「程序文件夹」
  - Then 弹出简体中文提示，而不是静默无反应

### US3 — 算法服务意外退出后自动拉起（P2）

- **Why P2**：与 US1 同一根因的另一处表现。
- **Independent test**：结束算法服务进程后，在任意应用中唤起输入法，观察输入法是否把服务拉起来。
- **Acceptance**：
  - Given 算法服务未运行
  - When 用户唤起输入法
  - Then 输入法把算法服务拉起，并恢复候选窗
  - Given 程序目录无法解析
  - When 用户唤起输入法
  - Then 不崩溃、不阻塞，输入法保持可用

## Functional Requirements

- **FR-001** 输入法前端 MUST 能解析出程序所在目录，解析依据是安装器**实际写入**的安装根值加上约定的二进制子目录。
- **FR-002** 解析 MUST 同时兼容安装器把注册表写进 32 位视图与 64 位视图两种情况（不得依赖调用方进程的字数）。
- **FR-003** 解析 MUST 优先使用火流猩自己的注册表键，旧版键只作兜底（旧版键读取必须继续可用，以便就地升级）。
- **FR-004** 当所有候选目录都不存在时，MUST 返回一个可供诊断的路径，而不是空串，且调用方 MUST 用简体中文告知用户。
- **FR-005** 启动算法服务时，MUST 优先使用安装器随附的启动脚本；脚本缺失时 MUST 退回到直接启动服务可执行文件。
- **FR-006** 解析与启动逻辑 MUST 收敛到**单一事实源**，输入法前端与单元测试 MUST 使用同一份实现。
- **FR-007** 本次改动 MUST NOT 改变任何用户数据路径、输入法方案行为、快捷键或进程间通信语义。

## Success Criteria

- **SC-001** 在已安装火流猩的机器上，点「重启算法服务」后算法服务进程 PID 发生变化。
- **SC-002** 在已安装火流猩的机器上，点「程序文件夹」能打开程序所在目录。
- **SC-003** 在已安装火流猩的机器上，结束算法服务后唤起输入法，服务能被拉起。
- **SC-004** 单元测试覆盖：安装根 → 程序目录的映射、候选目录筛选、启动目标选择；并含一条「旧逻辑解析不出」的对照断言。
- **SC-005** 全量测试与构建门禁通过，无新增编译告警。

## Out of Scope

- 不改安装器写入哪些注册表值（安装器保持只写安装根与用户数据根）。
- 不改旧版卸载逻辑里残留的旧键名读取。
- 不改输入法前端与服务进程之间的通信语义。
- 不做「自动更新」通道的注册表迁移。

## Edge Cases

- 安装器把注册表写在 32 位视图、而输入法前端是 64 位（**本机实测就是这个组合**）。
- 用户自定义安装目录（不在 `C:\Program Files` 下）。
- 安装目录带尾随分隔符。
- 安装目录是盘符根。
- 旧版火流猩/小狼毫与 fork 并存，机器上同时存在两套键。
- 安装损坏：注册表有值但目录不存在。

## Assumptions

- Windows 10/11。
- 目标机器的安装器按 fork 布局安装：程序在 `<安装根>\weasel`，用户数据在 `<安装根>\user1\fluxing`。
- 存在注册表值 `WeaselRoot` 的机器（少数由旧工具写入）仍按该值优先。
