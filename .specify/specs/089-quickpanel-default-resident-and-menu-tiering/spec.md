# 089 · Spec — 快速面板默认常驻、状态回显、静止不透明度与菜单分级

## Intent

1.1.4 真机反馈暴露四类可用性缺陷：

1. 「快速面板常驻」是一个需要用户主动勾选的开关，而且勾选后在语言栏的状态菜单里看不到勾选态，
   用户无法确认当前设置；用户的真实期望是「面板默认就常驻」，不需要先勾选。
2. 面板在鼠标不悬停时过淡，用户读不清面板上的状态与按钮。
3. 状态菜单把「重新部署」「重启算法服务」「退出算法服务」三个开发向动作与普通用户的日常动作
   平铺在同一层，普通用户容易误点；其中「退出算法服务」一点就让整个输入法不可用，且没有任何确认。
4. 「重启算法服务」名义上是重启，实际只是「再启动一次」：服务进程已经在跑时，这个动作不产生任何
   可观察效果，用户以为重启了、其实没有，也没有任何失败提示。

本 spec 把这四类缺陷一次修平：面板默认常驻且两处状态菜单都如实回显勾选态；静止态整块统一为
85% 不透明度；开发向动作收进「高级」子菜单；服务重启变成真正的「停 → 等退出 → 起」且失败可见；
退出前必须确认。

## User Stories

### US1 快速面板默认常驻，不需要用户先勾选 — Why P1

用户装完输入法，按 `Alt+,` 或在状态菜单里点「显示快捷设置栏」，面板就该一直在，不会 1.5 秒后
自己消失。不想看到它时用 `Alt+,` 或状态菜单取消即可。

- **Independent test**：在全新用户数据目录（从未写过任何面板状态记录）下打开面板，静置 3 秒以上，
  面板仍然可见；随后显式关闭常驻，再打开面板，静置约 1.5 秒面板自动消失。
- **Acceptance**
  - Given 全新用户数据目录、没有任何面板状态记录，When 用户打开快速面板并静置 3 秒，Then 面板保持可见。
  - Given 没有任何面板状态记录，When 用户查看状态菜单，Then「快速面板常驻」显示为勾选态。
  - Given 用户已显式关闭常驻，When 用户打开快速面板并静置约 1.5 秒，Then 面板自动消失。
  - Given 面板处于常驻态，When 用户按 `Alt+,`，Then 面板隐藏；再按一次恢复显示。
  - Given 用户显式关闭过常驻，When 重启输入法服务，Then 关闭状态被保留，不回到默认常驻。

### US2 两处状态菜单都如实回显「快速面板常驻」勾选态 — Why P1

用户在语言栏图标上右键看到的菜单，与在托盘图标上右键看到的菜单，必须对同一个开关给出同一个
勾选态；否则用户无从判断设置是否生效（1.1.4 的真实报错点就在这里）。

- **Independent test**：切换常驻开关，每次切换后分别打开语言栏菜单与托盘菜单，两处勾选态一致
  且与实际行为一致。
- **Acceptance**
  - Given 常驻为开，When 用户打开语言栏状态菜单，Then「快速面板常驻」带勾。
  - Given 常驻为关，When 用户打开语言栏状态菜单，Then「快速面板常驻」不带勾。
  - Given 用户在语言栏菜单里点掉该勾，When 再打开托盘菜单，Then 托盘菜单里该项也不带勾。
  - Given 全新用户数据目录，When 用户打开任一状态菜单，Then 该项带勾（与 US1 的默认值一致）。

### US3 面板静止态整块统一为 85% 不透明度 — Why P1

用户要求「鼠标不悬停时透明度 15%」。当前实现里图标区与文字区偏实、面板底色偏虚，而且底色自身
上实下虚，同一块面板明暗不一，用户感知为「过淡、看不清」。

- **Independent test**：面板静止、鼠标不在面板上时，取面板顶部、中部、底部三处底色像素，
  三处不透明度一致且等于 85%；鼠标移入后恢复为完全不透明。
- **Acceptance**
  - Given 面板静止且鼠标不在面板上，When 测量面板底色，Then 顶部/中部/底部的不透明度均为 85%。
  - Given 面板静止且鼠标不在面板上，When 测量图标与文字等前景内容，Then 不透明度同样为 85%，
    与底色一致，不出现「只有图标变亮」的局部效果。
  - Given 鼠标移入面板，When 过渡结束，Then 整块恢复为完全不透明。
  - Given 鼠标移出面板，When 过渡结束，Then 整块回到 85% 不透明。

### US4 开发向动作收进「高级」子菜单 — Why P2

普通用户日常只需要「显示快捷设置栏 / 快速面板常驻 / 中英文切换 / 简繁切换 / 全半角切换 /
用户文件夹 / 恢复已忽略的候选项」。把「重新部署」「重启输入法服务」「退出输入法服务」这三个
会影响服务生命周期的动作收进「高级」子菜单，降低误点概率。

- **Independent test**：打开语言栏与托盘两处状态菜单，主菜单不再直接出现这三个动作；展开「高级」
  子菜单后三者都在，且点击后行为与收进子菜单之前一致。
- **Acceptance**
  - Given 用户打开语言栏状态菜单，When 查看主菜单，Then 不出现「重新部署」「重启输入法服务」
    「退出输入法服务」，出现「高级」子菜单。
  - Given 用户展开「高级」子菜单，Then 三个动作都在其中。
  - Given 用户打开托盘状态菜单，When 查看主菜单，Then 同样只通过「高级」子菜单访问这三个动作。
  - Given 菜单语言为简体中文/繁体中文/英文，Then 三套语言的子菜单标题与条目文案都已本地化。

### US5 「重启输入法服务」是真正的重启，且失败可感知 — Why P1

用户点这个动作时期待的是「服务被停掉再起来」。当前实现只启动不停止，服务已在运行时等于没做；
而且它只在语言栏菜单里存在，托盘菜单里根本没有这一项。

- **Independent test**：记录服务进程标识，点击「重启输入法服务」，等待提示消失后再次读取服务进程
  标识，两次标识不同；把服务脚本改名制造失败，点击后必须弹出简体中文失败提示。
- **Acceptance**
  - Given 输入法服务正在运行，When 用户从语言栏或托盘点击「重启输入法服务」，Then 服务被停止后
    重新拉起，进程标识发生变化。
  - Given 重启所需的服务脚本缺失或当前用户无权操作服务，When 用户点击该动作，Then 弹出简体中文
    失败提示说明原因，且不把服务留在停止状态。
  - Given 用户在托盘菜单点击该动作，When 执行成功或失败，Then 提示行为与语言栏路径一致。
  - Given 重启过程中服务自身被停止，Then 重启流程不因发起进程消失而中断。

### US6 退出输入法服务前必须确认 — Why P2

退出会让输入法整体不可用，且需要重新登录或重启电脑才恢复。这个后果当前没有任何提示。

- **Independent test**：从语言栏或托盘点击「退出输入法服务」，必须先出现简体中文确认对话框；
  选择「否」后服务仍在运行。
- **Acceptance**
  - Given 用户点击「退出输入法服务」，When 动作被受理，Then 先弹出简体中文确认框，明确说明
    「退出后输入法将不可用，需要重新登录或重启电脑才能恢复」。
  - Given 确认框已弹出，When 用户选择取消，Then 服务继续运行，状态不变。
  - Given 确认框已弹出，When 用户选择确认，Then 服务停止。
  - Given 用户从语言栏路径或托盘路径触发，Then 确认框只出现一次，两条路径行为一致。

## Functional Requirements

- **FR-001** 面板常驻的默认值 MUST 为「开」。判定依据 MUST 是「用户是否显式写过这个开关」：
  从未写过 ⇒ 开；写过 ⇒ 按写入值。
- **FR-002** 已有的显式选择 MUST 被保留。用户关闭常驻后重启服务，MUST NOT 回到默认常驻。
- **FR-003** 自动消失的时长 MUST 沿用现有的 1.5 秒，且该数值 MUST 以命名常量表达，
  MUST NOT 以裸字面量散落在逻辑里。
- **FR-004** 语言栏状态菜单 MUST 在弹出前把「快速面板常驻」的勾选态刷成当前真实值；勾选态的
  取值来源 MUST 与托盘菜单一致（同一份持久化状态、同一个默认值规则）。
- **FR-005** 托盘菜单的既有勾选态行为 MUST NOT 回归。
- **FR-006** 面板静止态的不透明度 MUST 为 85%，且 MUST 对整块面板均匀生效（底色、图标、文字
  同一个值）。MUST NOT 保留「顶部实、底部虚」的静止态渐变。
- **FR-007** 悬停态 MUST 仍为完全不透明；静止态与悬停态之间的渐变过渡行为 MUST NOT 回归。
- **FR-008** 「重新部署」「重启输入法服务」「退出输入法服务」三项 MUST 位于「高级」子菜单内，
  MUST NOT 出现在主菜单层。语言栏与托盘两处菜单 MUST 一致。
- **FR-009** 三套菜单语言（简体中文 / 繁体中文 / 英文）MUST 全部同步上述结构调整与文案调整；
  「重启算法服务」的用户可见文案 MUST 改为「重启输入法服务」（英文与繁体对应本地化）。
- **FR-010** 「重启输入法服务」MUST 实现为「停止服务 → 等待服务进程真正退出 → 启动服务」。
  MUST NOT 采用「再启动一个实例去顶掉旧实例」的做法。
- **FR-011** 重启动作 MUST NOT 因为发起它的进程自身被停止而中断；执行链 MUST 脱离服务进程生命周期。
- **FR-012** 重启的前置条件（当前用户有权操作服务、停止与启动脚本都存在）MUST 在执行前检查；
  任一不满足 MUST 弹出简体中文提示并 MUST NOT 把服务留在停止状态。
- **FR-013** 「重启输入法服务」MUST 同时出现在语言栏菜单与托盘菜单，且两条路径 MUST 共用同一份
  执行逻辑，MUST NOT 各写一套。
- **FR-014** 「退出输入法服务」MUST 先弹简体中文确认框；确认框 MUST 只弹一次，无论从哪条路径触发。
- **FR-015** 所有新增的用户可见字符串 MUST 为简体中文（繁体/英文菜单项按既有三语言块本地化）。
- **FR-016** 状态菜单弹出前的勾选态刷新 MUST NOT 引入可感知卡顿；MUST NOT 在文本输入处理回调
  链路内做阻塞式输入输出。
- **FR-017** 本轮 MUST NOT 新增任何进程间通信消息类型。

## Success Criteria

- **SC-001** 全新用户数据目录下，面板打开后静置 5 秒不消失；语言栏与托盘两处菜单该项均带勾。
- **SC-002** 显式关闭常驻后，面板约 1.5 秒自动消失；重启服务后仍是关闭态；两处菜单均不带勾。
- **SC-003** 静止态面板顶部/中部/底部三处底色的不透明度实测均为 85%（±1），前景与底色一致。
- **SC-004** 鼠标移入/移出面板时透明度渐变仍平滑，无闪烁、无残影、无「跳变到全透明」。
- **SC-005** 语言栏与托盘主菜单均不含三个开发向动作；「高级」子菜单内三项均可正常触发。
- **SC-006** 点击「重启输入法服务」后服务进程标识发生变化，输入法在数秒内恢复可用；人为制造
  脚本缺失时弹出简体中文失败提示且服务未被停掉。
- **SC-007** 点击「退出输入法服务」先出现简体中文确认框，取消后服务仍在运行。
- **SC-008** 既有面板回归项（`Alt+,` 开关、ESC 不隐藏、拖拽、按钮点击、状态文件落在用户数据目录、
  旧版状态文件迁移）全部保持通过。
