# 090 · Spec — Shift 翻页后按页内次序选词，以及右键屏蔽候选词

## Intent

1.1.4 真机反馈里有两条落在候选词交互上：

1. 用左右 Shift 选第 2、第 3 个候选时，只要翻过页，上屏的仍然是**第一页**的第 2、第 3 个词。
   用户看到的是「我明明翻到第 2 页了，Shift 却给我第 1 页的词」。
2. 用户希望在候选窗口出现后，能把某个不想再看到的词去掉：自己造的詞直接从用户词典里删除，
   系统词典里的词则以后不再显示。用户记得「以前右键点候选词就能做到」，问能否恢复。

第 1 条是明确的缺陷：选词走的是「全候选列表的绝对次序」，而用户的心智模型是「当前这一页里的次序」。
第 2 条经取证是一个**从未接线**的半成品：屏蔽名单的读取、过滤、写入三段逻辑都已经存在，
右键按下时也有命中判定，但两者之间没有任何一条调用路径把它们连起来，所以这个能力自始至终没有对用户
暴露过。用户记忆中的「右键屏蔽」不来自本项目的任何历史版本。

用户还提到「`Shift+Ctrl+数字` 按次序移除/隐藏候选」。取证结论是：本项目**从未存在**这个快捷键
（没有需求记录、没有按键绑定、没有对应的进程间命令、没有处理入口），因此它属于**新功能**而不是
「恢复」。它需要新增按键拦截与新的进程间命令，牵涉输入处理回调的阻塞限制与四边同步，
验收成本与本轮两条缺陷不在同一量级 ⇒ **本轮不实现**，记为后续独立需求（见 FR-016）。
本轮交付右键这一条路径，它已经能覆盖「删除自造词 / 隐藏系统词」的全部效果。

这两条必须一起改：屏蔽会改变当前页的词数与次序，如果只改 Shift 的选词语义而不统一「页内次序 →
引擎次序」的换算，屏蔽一生效，Shift 和数字键就会选到别的词，反而制造新缺陷。

## User Stories

### US1 Shift 选词遵循「当前页内的次序」 — Why P1

用户翻到第 2 页，按左 Shift 应该上屏第 2 页的第 2 个词，按右 Shift 应该上屏第 2 页的第 3 个词。

- **Independent test**：输入一个候选数超过一页的拼音，翻到第 2 页，分别按左 Shift 与右 Shift，
  核对上屏的词与第 2 页第 2、第 3 位显示一致。
- **Acceptance**
  - Given 候选窗口已打开且停在第 1 页，When 用户按左 Shift，Then 上屏第 1 页第 2 个候选。
  - Given 候选窗口已打开且停在第 1 页，When 用户按右 Shift，Then 上屏第 1 页第 3 个候选。
  - Given 用户已翻到第 2 页，When 用户按左 Shift，Then 上屏**第 2 页**第 2 个候选，
    而不是第 1 页第 2 个。
  - Given 用户已翻到第 2 页，When 用户按右 Shift，Then 上屏**第 2 页**第 3 个候选。
  - Given 当前页只有 2 个候选（例如最后一页不满），When 用户按右 Shift，Then 不上屏任何词、
    不报错、候选窗口保持原状（MUST NOT 退回去选别页的词）。
  - Given 当前页只有 1 个候选，When 用户按左 Shift，Then 同上，不选词、不报错。
  - Given 候选窗口未打开，When 用户按 Shift，Then 既有的中英切换行为不受影响。

### US2 右键点候选词即可删除自造词或隐藏系统词 — Why P1

用户在候选窗口里把鼠标移到某个词上点右键：如果那是自己造的詞，直接从用户词典里删掉；
如果是系统词典里的词，记进屏蔽名单，以后不再出现。

- **Independent test**：输入拼音出候选，右键点一个系统词典词，重新输入同一个拼音，该词不再出现；
  右键点一个自造词，重新输入，该词也不再出现；用户数据目录下生成对应的屏蔽名单文件。
- **Acceptance**
  - Given 候选窗口已打开且鼠标停在某个候选上，When 用户点右键，Then 该候选被处理（删除或屏蔽），
    并有可观察的界面反馈。
  - Given 被右键点击的是自造词，When 处理完成，Then 该词从用户词典中删除，重新输入不再出现。
  - Given 被右键点击的是系统词典词，When 处理完成，Then 该词被写入当前输入方案的屏蔽名单，
    重新输入不再出现。
  - Given 鼠标没有停在任何候选上，When 用户点右键，Then 什么都不发生（不弹菜单、不误删）。
  - Given 用户连续快速右键点击同一个候选，When 间隔小于去抖阈值，Then 只处理一次。
  - Given 用户已屏蔽了若干词，When 从状态菜单点「恢复已忽略的候选项」，Then 屏蔽名单被清空，
    这些词重新出现。

### US3 屏蔽生效后，所有按次序选词的入口都不错位 — Why P1

屏蔽会让当前页少一个词，页内次序随之改变。数字键、Shift、鼠标悬停高亮、右键删除这四个入口
必须对「第几个」有同一套理解，否则会选到相邻的另一个词。

- **Independent test**：屏蔽掉当前页第 1 个词后，用数字键 `1`、左 Shift、右键分别操作，
  核对每个入口命中的都是**界面上显示的那一个**词，而不是引擎内部次序相邻的另一个词。
- **Acceptance**
  - Given 当前页有词被屏蔽，When 用户按数字键选第 N 个，Then 上屏的是界面上第 N 个显示出来的词。
  - Given 当前页有词被屏蔽，When 用户按左/右 Shift，Then 上屏的是界面上第 2/第 3 个显示出来的词。
  - Given 当前页有词被屏蔽，When 用户右键某个词，Then 被处理的正是鼠标下方那个词。
  - Given 当前页的词被屏蔽到只剩 0 个，When 界面刷新，Then 候选窗口按既有的空候选行为处理，
    不崩溃、不残留上一轮的词。
  - Given 屏蔽名单在两次输入之间被外部修改（例如「恢复已忽略的候选项」清空了名单），
    When 用户下一次输入，Then 新的名单生效。

### US4 屏蔽名单落在用户数据目录、按输入方案分开 — Why P2

屏蔽是用户的个人偏好，必须跟着用户数据目录走，且不同输入方案互不干扰。

- **Independent test**：屏蔽一个词后检查用户数据目录下是否生成 `<方案标识>.user_ignore.txt`；
  切换到另一个输入方案屏蔽另一个词，确认生成的是另一个文件；确认旧版漫游目录下没有被新建任何东西。
- **Acceptance**
  - Given 用户屏蔽了某个词，When 检查用户数据目录，Then 存在以当前输入方案命名的屏蔽名单文件，
    内容包含被屏蔽的词。
  - Given 用户切换到另一个输入方案并屏蔽词，Then 名单写入另一个方案对应的文件，两个方案互不影响。
  - Given 屏蔽名单文件已存在，When 用户再屏蔽一个词，Then 新词被追加，已有内容不丢失。
  - Given 整个流程，Then 旧版漫游目录 MUST NOT 被新建。

## Functional Requirements

- **FR-001** Shift 选词 MUST 使用「当前页内的次序」（左 Shift = 页内第 2 个，右 Shift = 页内第 3 个），
  MUST NOT 使用「全候选列表的绝对次序」。
- **FR-002** 当页内目标次序超出当前页实际候选数时，MUST NOT 选词、MUST NOT 报错、
  MUST NOT 退回去选其它页的候选；候选窗口状态保持不变。
- **FR-003** 「页内次序 → 引擎次序」的换算 MUST 抽成可脱机测试的纯函数，MUST NOT 把裸的下标运算
  散落在按键处理逻辑里。
- **FR-004** Shift 选词后既有的上屏/暂存行为（部分选词时的 flush 判据）MUST NOT 回归。
- **FR-005** 候选屏蔽的过滤 MUST 发生在候选信息下发给界面之前，且 MUST 只有这一处过滤点；
  界面层 MUST NOT 再做第二次过滤（双重过滤会导致次序错位）。
- **FR-006** 过滤 MUST 同时维护「界面可见次序 → 引擎次序」的映射，且所有按页内次序选词的入口
  （数字键、Shift、悬停高亮、右键删除）MUST 先经该映射换算再下发给引擎。
- **FR-007** 右键点候选 MUST 把该候选**无条件写入屏蔽名单**，同时照常尝试引擎剔除。
  > **收尾修订（2026-10-30）**：原「按是否自造词分流（能删则删、删不掉才写名单）」**已作废**。
  > 取证：`librime/src/rime/context.cc:146-154` 中 `Context::DeleteCandidate` 恒返回 `true`；
  > `rime_api_impl.h:982-1000` 的 `false` 分支全部是参数/状态校验失败；C API 不提供 `is_user_dict`。
  > ⇒ 返回值**不携带**「是否自造词」信息，分流无判据。实现改为无条件写名单（保证系统词也消失），
  > 同时仍调引擎剔除（自造词能被真删掉，不留脏数据），返回值不参与任何判断。
  > 详见 `docs/adr/0023-*.md` D5 的收尾修订。撤销入口沿用既有托盘「恢复已忽略的候选项」。
  判定 MUST 以引擎的实际删除结果为准，MUST NOT 靠界面侧猜测。
- **FR-008** 屏蔽名单 MUST 按输入方案分文件存放在用户数据目录，追加写入 MUST NOT 丢失已有内容，
  编码 MUST 与既有名单文件保持兼容（可被既有的读取逻辑正确解析）。
- **FR-009** 屏蔽一个词后，当前页 MAY 不立即重排；但下一次输入 MUST 不再出现该词。
- **FR-010** 状态菜单的「恢复已忽略的候选项」MUST 仍能清空屏蔽名单并使被屏蔽的词恢复。
- **FR-011** 鼠标没有停在任何候选上时，右键 MUST 是无操作。
- **FR-012** 右键连点 MUST 沿用既有的去抖阈值，同一候选在阈值内 MUST 只处理一次。
- **FR-013** 本轮 MUST NOT 新增任何进程间通信消息类型（屏蔽与删除复用既有命令与文件）。
- **FR-014** 界面层 MUST NOT 在文本输入处理回调链路内做阻塞式输入输出。
- **FR-015** 所有新增的用户可见字符串 MUST 为简体中文。
- **FR-016** `Shift+Ctrl+数字` 按次序移除/隐藏候选 MUST NOT 在本轮实现；该需求 MUST 被记录为
  独立的后续需求（含其需要新增按键拦截与新的进程间命令这一事实），MUST NOT 被静默丢弃。

## Success Criteria

- **SC-001** 候选数超过一页的拼音，翻到第 2 页后左/右 Shift 上屏的词与第 2 页第 2/第 3 位显示一致；
  在第 1 页时行为与 1.1.4 相同。
- **SC-002** 最后一页只剩 2 个候选时按右 Shift，无词上屏、无报错、候选窗口不关闭。
- **SC-003** 右键一个系统词典词后重新输入同一拼音，该词不再出现；用户数据目录下生成
  `<方案标识>.user_ignore.txt` 且内容含该词；旧版漫游目录未被新建。
- **SC-004** 右键一个自造词后重新输入，该词不再出现，且未被写进屏蔽名单（走的是删除路径）。
- **SC-005** 屏蔽掉当前页第 1 个词后，数字键 `1`、左 Shift、右键三个入口命中的都是界面上
  显示的那个词，无错位。
- **SC-006** 「恢复已忽略的候选项」清空名单后，被屏蔽的词重新出现。
- **SC-007** 既有回归项全部通过：Shift 双击切英文、CapsLock 关闭态下的选词/翻页/中英切换、
  右键去抖、空候选窗口行为。
