## 技术方案

### 方案 A（US1）：把两条无条件切换键挪出 `Ctrl+Shift+数字` 家族

**根因**（L163 已坐实）：删词键是**条件性拦截**——只有候选窗开着且目标序号存在时前端才吃掉这个键，否则按设计放行；而标点/简繁切换是 `when: always` 的**无条件兜底**。两者共用同一族 chord 时，删词失败的每一次都会落到兜底上，把标点静默翻过去。又因为该开关刻意不设「每次部署复位」（需要记忆的开关不能复位），一次误触会一直持续到用户手动切回。

**修法**：不动条件性拦截的那一方（它是用户真正想要的功能），把无条件兜底的两条搬出该家族。新键位不凭空发明，取仓库里早已写好但被注释掉的社区推荐块，因此有既有出处、不是拍脑袋。

**为什么改出货配置本体而不是用户侧定制副本**：门禁是对原始文件做扫描、不解析补丁层；在定制副本里重述全部绑定会让源门禁计数从 39 冲到 66，直接破基线。且仓库已有「直接改本体删冗余 chord」的先例。用户侧定制副本的禁改规则针对的是「复制整份默认文件再改副本」，与本做法不同。

**为什么不给开关加复位**：项目自己明写「需要记忆的开关不能设定复位」；而且加复位只是把误触的后果藏起来，冲突仍在。

**为什么不重引入第四个 `Ctrl+Shift+数字` 绑定**：该 chord 曾被明确当作冗余重复删掉过。

### 方案 B（US2）：给锁定降级的落地文件名加「每次安装唯一」序号

**根因**（L164 已坐实）：降级用的版本化文件名只由版本号与构建号决定，没有每次安装唯一的分量。第二次同版本覆盖安装时，该名字已被上一次的副本占着且正被映射 ⇒ 删除静默失败 ⇒ 写入落不进去 ⇒ 退回「等重启再换」。

**修法**：文件名尾部加一个序号，安装时从 0 起探测「最低的空闲序号」。探测手段就是既有的删除动作本身——删除对不存在的文件成功、对未映射的存在文件真删掉、对被映射的文件失败，所以探测同时兼作回收。序号有上界（64），触界时名字必然仍被占用，写入失败 ⇒ 落回既有的降级分支，行为与改动前一致，不引入新失败模式。

**关键前置事实**：版本化分支只在「改名普通模块文件失败」时才进入 ⇒ 要复现它，门禁必须**同时**独占锁住普通名文件与当前最大序号的副本，只锁一个进不去这条路径。

**明确不采纳**：常驻转发层。理由见 ADR 0028。

### 方案 C（US3）：修门禁自身的两类静默腐化

1. **选包正则与版本命名约定脱节**（L165）：版本命名约定改成三段式之后，门禁仍在用四段式正则挑待验包 ⇒ 一个也匹配不上 ⇒ 静默判失败退出。权威门禁自三段式启用以来从未真正验过任何一个包。修法是把正则的第四段变成可选，并在缺省时兜底；**不改**构建产物的命名（三段式是刻意设计，第四段只进内部资源与版本化文件名）。四处站点全部同步。
2. **断言编号撞号**（L165）：新增断言前必须先枚举既有编号。原计划的编号已被另一阶段占用（且那里本身已有同一编号出现两次的既有缺陷），改用完全空闲的新前缀。
3. **新增阶段**：针对方案 B 的验收点做自动断言，其中「不产生等重启标记」是判别性主断言。
4. **既有阶段也要改**：原先靠从包名反推构建号来拼版本化文件名，三段式之后必然推错 ⇒ 改成从文件系统反查真实副本名（取序号最大者）。这同时解除了「必须以发布模式构建才能跑门禁」这个隐含前置条件。

## 门禁与验证策略

| 层 | 手段 | 判据 |
| --- | --- | --- |
| 键位 | 快捷键门禁五条调用 | 出货配置 `bindings=39 reachable=39 dead=0 mismatches=0`；负控制、录制样本、映射自检、录制自检全 PASS |
| 键位 | 部署后复跑部署产物门禁 | `dead=0`，且临时目录里无非法绑定告警 |
| 键位 | 用户物理按键 | US1 的 6 条 |
| 安装 | 语法门禁 | 安装脚本编译零错误 |
| 安装 | 运行时变量展开探针 | 最小安装脚本证明写入目标名会展开运行时变量（否则序号方案根本无效） |
| 安装 | **权威隔离环境门禁**（强制） | 约 46 项断言，含新增阶段；机器可读报告 + 日志落盘并进提交信息 |
| 门禁自身 | 字节级编码校验 + 语法解析 | 零解析错误；编码与行尾符合仓库约定 |
| 门禁自身 | 选包正则三样本自测 | 三段式包名应选中 / 四段式基线包应仍作升级基线 / 垃圾名应排除 |

**已知恒失败项**（隔离环境的固有限制，非本 spec 回归）：只有系统盘、默认无外网、需要真实输入法客户端触发的激活通知。判定标准是「失败项集合没有意外扩大」，不是「零失败」。

## 提交拆分

按 `hotkey-binding.md` 的反模式要求，配置层键位改动与 C++ 改动**不得同一提交**：

1. `fix(fluxing): 中英标点／简繁切换键让出 Ctrl+Shift+数字族` — 出货配置 + 说明书 + 变更日志 + L163 + 本 spec 三件套 + ADR 0028
2. `fix(installer): 锁定降级文件名加每次安装唯一序号` — 安装脚本 + L164 + 门禁脚本 + L165
3. `docs(WeaselTSF): 修正已过时的键位注释` — 仅注释，独立提交
4. `test(TestHotkeyBindings): 修正已过时的已知死绑定说明` — 仅文本

## 风险

| 风险 | 缓解 |
| --- | --- |
| 用户已经习惯了旧键位 | 变更日志给出新旧对照；说明书 5 处同步；旧键位在删词场景下本来就是误触源 |
| 序号探测把上一次的副本删掉，而它仍被某进程映射 | 删除对被映射文件失败 ⇒ 探测自然跳过；不会误删正在用的副本 |
| 门禁改动本身引入新缺陷 | 四步校验（编码 / 语法 / 正则自测 / 版本号抬升）+ 一整轮真跑 |
| 隔离环境门禁耗时 10–25 分钟 | 后台跑，期间并发写文档（已确认构建的资产暂存只涉及三个被忽略的文本产物，不含变更日志 / 事故记录 / ADR / 操作手册） |
