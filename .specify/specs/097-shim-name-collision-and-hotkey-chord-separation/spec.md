# Spec 097 — 锁定降级文件名撞车，与快捷键 chord 家族冲突

- **Status**: Implemented (pending on-device acceptance for US1, pending gate run for US2)
- **Created**: 2026-11-01
- **Priority**: P1
- **Lessons**: L163（chord 家族冲突）、L164（降级文件名撞车）、L165（门禁自身腐化）
- **ADR**: 0028

---

## 背景（一句话）

用户报了两个互相独立、但都表现为「我以为按了 A，结果发生了 B」的问题：一个在按键层，一个在安装层。

---

## 用户故事

### US1 — 按删词键时不应该静默切换标点

**作为**一名用「删词」快捷键清理候选词的用户，
**我希望**按下删词键时，只有候选窗开着且目标序号存在才发生删词、否则什么都不发生，
**以便**我不会在删词失败的同时被静默改掉标点或简繁状态，之后一直打出错误的标点却找不到原因。

**验收标准**

1. **Given** 候选窗未打开（或可见候选少于 3 个），**When** 用户按下 `Ctrl+Shift+3`，**Then** 不发生删词，**并且** 中英标点状态不改变、简繁状态不改变。
2. **Given** 候选窗打开且第 3 个候选存在，**When** 用户按下 `Ctrl+Shift+3`，**Then** 该词从用户词库中删除。
3. **Given** 任意状态，**When** 用户按下中英标点切换键，**Then** 中英标点状态翻转；该键不再是 `Ctrl+Shift+数字` 家族里的任何一个。
4. **Given** 任意状态，**When** 用户按下简繁切换键，**Then** 简繁状态翻转；该键不再是 `Ctrl+Shift+数字` 家族里的任何一个。
5. **Then** 全半角的键位分配与本 spec 之前完全一致（仍然没有绑定任何热键），不得顺手给用户加一个他没要求的键位。
6. **Then** 用户可见的说明书、变更日志里都能查到新旧键位对照；键位改动不得静默发生。

### US2 — 覆盖安装不应该要求重启系统

**作为**一名在没有管理员窗口、也不想重启电脑的情况下更新输入法的用户，
**我希望**即使在更新时输入法模块正被其他程序占用，覆盖安装也能当场完成，
**以便**我不必等下一次开机才用上新版本。

**验收标准**

1. **Given** 已安装版本 X，且输入法模块文件正被一个 64 位程序映射（无法删除、无法改名），**When** 用同一个版本 X 再次覆盖安装，**Then** 安装以成功退出码结束。
2. **Then** 安装目录里出现一个此前不存在的、名字带「本次安装唯一序号」的模块副本，其内容与本次构建产物逐字节一致。
3. **Then** 系统的输入法注册指向那个新副本，而不是指向旧的被占用文件。
4. **Then** 不产生「等重启再换」的待处理标记（这是本 spec 的**判别性**验收点：旧实现下这一条必然失败）。
5. **Then** 32 位与 64 位两条分支的序号策略对称（都从最小空闲序号起探测）。
6. **Then** 序号探测有上界，不会因为磁盘上的残留文件无限循环；触到上界时退回既有的降级行为，不引入新的失败模式。
7. **Then** 卸载时所有序号的副本都被清掉，不在用户机器上留垃圾。

### US3 — 门禁必须能咬住这两类回归

**作为**后续维护这个仓库的人，
**我希望**权威安装门禁真的会验到待发布的安装包、并且断言编号不会撞车，
**以便**「门禁跑过了」这句话是有意义的，而不是恒真的仪式。

**验收标准**

1. **Given** 构建产物的文件名遵循三段式版本号约定，**When** 跑权威安装门禁，**Then** 它能选中该文件作为待验包（旧门禁在此处静默选不中，直接判失败退出）。
2. **Given** 门禁里已有若干组断言编号，**When** 新增一组断言，**Then** 新编号与既有编号零重叠；产出的机器可读报告里每个编号只出现应有的次数。
3. **Then** 针对 US2 的验收点 4 存在一条会真失败的断言（负控制：把它跑在旧实现上必须失败）。
4. **Then** 门禁脚本自身通过字节级编码校验与语法解析校验，零解析错误。

## 范围

### 在范围内

- 键位分配的调整（哪些功能绑在哪些键上）。
- 安装时模块文件被占用情况下的落地文件名策略与注册指向。
- 权威安装门禁的选包规则、断言编号、以及针对上述落地策略的新断言。
- 上述三者对应的用户可见文档同步。

### 不在范围内

- 不引入常驻转发层（「永不改名的固定入口 + 转发到真实实现」）。它解决的问题与本 spec 的序号方案高度重叠，但多出一个需要签名、需要验证与系统保护进程及加载器交互的二进制，风险明显更高。记为备选，未采纳。
- 不冻结任何版本化文件的名字。
- 不改用户数据目录的位置。
- 不修「快捷面板双击不上屏」（另有独立排查，见交接文档诉求 2）。

## 成功判据

- US1 的 6 条验收标准全部由用户物理按键确认。
- US2 的 7 条验收标准全部由一次性隔离环境的权威门禁自动判定，报告落盘。
- US3 的 4 条验收标准全部满足。
- 三条事故教训（L163 / L164 / L165）写入事故记录，且代码与脚本里的引用都能解析到真实条目。
