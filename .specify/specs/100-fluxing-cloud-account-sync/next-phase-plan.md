## 4. 明确不做（首版边界，避免反复讨论）

1. **不做**「同步自造词 / 短语 / 配置」之外的任何数据出向；未登录时出向请求数必须 = 0（AC-12 / R9）。
2. **不做**服务端解密：服务端只见密文，`enc_key` 永不出本机（ADR 0039）。
3. **不做** `WeaselDeployer` 账号入口 —— 会触发 IPC 四边同步（`include/WeaselIPCData.h` 变更 + 三端 + ADR + `test/TestWeaselIPC`），首版否决（T402 已记录）。
4. **不做**恢复 `WeaselServer` 托盘图标作为账号入口（`output/data/weasel.yaml:81 display_tray_icon: false` 是用户主动关的）。
5. **不做** Web 端管理后台；设备管理只在桌面端。
6. **不做**「口令找回」—— 口令派生密钥，遗忘即云端数据不可恢复，这条要在文案里明写（T403）。

## 8. 分支策略与首条反馈的处置

### 8.1 分支策略（D5）：按批次分阶段合流，而不是攒到发版才合

- **长期分支**：`feat/100-cloud-sync`，自 `Fluxing@1b022f3` 切出。
- **合流节拍**：**批次 X（纯取证 + 测试工程，零运行时行为）完成后立即合回 `Fluxing`**；Y/Z 同理。**从阶段 D 起**（真改 `WeaselServer`/TSF 运行时、需要装机）才让分支长期存活，直到阶段 G 验收通过再整体合入。
- **为什么不一刀切攒到最后**：本仓所有 handoff / `CLAUDE.md` / `.specify` 指针都按「当前 HEAD」写；长期分叉会让下个会话在 `Fluxing` 上找不到产物，且本机存在并发会话（`RimeWithWeasel.cpp` 假脏即证）。
- **合流前三件必查**：① `git status -sb` 不得带 `RimeWithWeasel/RimeWithWeasel.cpp` / `librime` 假脏；② 提交走 Conventional Commits；③ 分支产物若上过机，handoff 必须记 `branch@sha`，否则复验会拿主分支二进制对比错。

### 8.2 第 1 条反馈（托盘仍有中英文图标）的处置口径

- 批次 W 修复的是**我方语言栏项**：`kLangBarRegisterItem = false`，真机探针 `INPUT_INDICATOR_COUNT` 2→1、`OUR_TOOLTIP_HIT=0`。
