## 背景（一句话）

搜狗等主流输入法能在本地词库给不出最贴切的词时，把更贴合当前语境的词补进候选，
这是用户从搜狗迁到火流猩最容易感到"少了点什么"的能力之一；
火流猩要的是**这份体验**，不是**它的实现方式** ——
不广告、不弹窗、不擅自联网、不上传设备信息与用户画像，连哪儿由用户自己指定。

## 与 010-cloud-sync 的关系（互不覆盖）

| | 010-cloud-sync | **098 本 spec** |
|---|---|---|
| 做什么 | 把**用户自己的资产**（个人词库、配置）在**自己的设备之间**同步 | 打字**当下**向服务端**借用别人的词** |
| 时机 | 低频、可后台、可等待（分钟级） | 高频、在输入热路径旁路（毫秒级，慢就等于没有） |
| 数据方向 | 上 + 下（双向，带冲突合并） | 上（发送拼音片段）+ 下（返回候选词），**不落库、不合并** |
| 失败后果 | 资产暂时不一致 | 只是少几个候选，本地结果照常上屏 |

可复用的通道：两者共用同一套**网络边界口径**（默认关 + 端点白名单 + 无埋点）与
同一套后端账号/部署设想；但 **098 不依赖 010 落地**，010 也不得被 098 拖进输入热路径。

## 用户故事

### US1 — 想说的词更靠前
作为从搜狗迁移过来的用户，我希望在本地候选不够理想时，候选里出现更贴合当前语境的词，
好少翻页、少拼第二遍。
**验收**：给定一个本地词库覆盖差的长拼音片段，开启云候选后，候选区出现至少一条云端补充词，
且本地候选的原有条目全部仍在、相对顺序不变。

### US2 — 不开就一个包都不发
作为从不关心云功能的用户，我希望默认状态下输入法跟没这功能时完全一样。
**验收**：出厂默认配置下，用任意输入序列（含连续快速输入、翻页、选词、切中英文）操作，
网络侧抓到 **0 条**出向请求；本 spec 全部性能基线数字与功能上线前一致。

### US3 — 连哪儿我说了算
作为注重隐私的用户，我希望只有在白名单里的地址才会被连接，白名单为空就等于没有这个功能。
**验收**：白名单为空 → 开关打开也无法得到云端词，且无报错弹窗；
白名单只含 `example.com` → 请求其它主机的代码路径全部不可达（用例证明被拒）。

### US4 — 网慢不能拖慢我打字
作为用户，我希望网络再慢、再断，也不影响本地候选的出现和上屏。
**验收**：三种降级各自通过 ——
① **断网**：本地候选照常，无卡顿、无重试风暴；
② **超时**（服务端故意拖延超过阈值）：云端词静默消失，本地候选与上屏延迟无可感知变化；
③ **白名单空**：直接不发请求，行为等同 US2。

### US5 — 我只交出最少的那几个字母
作为用户，我希望发出去的东西只是当前拼音片段本身，不含任何能认出"我是我"的信息。
**验收**：抓包内容仅含拼音片段与必要的协议字段；不含设备标识、账号、应用清单、位置、
剪贴板内容、已装软件列表；本地不留任何把输入内容与设备关联的明文日志。

### US6 — 云端词要能像本地词一样被选中
作为用户，我希望云端补的词能用同样的方式选中和上屏，不需要记新规矩。
**验收**：云端词可被数字键或翻页选词上屏；选它**不会**改变本地候选的编号与位置；
是否写入个人词库由配置决定，默认**不写**。

### US7 — 一键退回
作为维护者，我希望能在不改代码、不重装的前提下把云候选整体关掉，
关掉后的行为与这个功能从未存在过一致。
**验收**：一处开关 + 白名单清空两条路径都能停用；停用后回到 US2 的 0 请求状态。

### US8 — 我们的红线不越界
作为项目维护者，我希望这个能力不把我们带回"联网全家桶"。
**验收**：功能里找不到广告位、更新检查、崩溃上报、行为统计中的任何一项；
连接的默认主机表里不含任何搜狗端点。

## 范围

**在范围内**
- 输入时按拼音片段向用户自建的端点请求补充候选词，并把结果呈现进候选区。
- 开关（默认关）、端点白名单、超时与降级策略、隐私最小化口径。
- 云端候选与本地候选的可区分呈现与选词/上屏语义。

**不在范围内**
- 用户词库/配置的跨设备同步（= 010）。
- 云端整句改写、AI 续写、语音输入、表情/皮肤等云端内容分发。
- 任何自带域名、自带账号或自带遥测的服务端；服务端由用户/我们自己另行部署。
- 广告、弹窗推广、更新检查、崩溃上报、行为埋点。

## 功能需求

- **FR-001 默认关闭**：出厂默认状态下本功能不生效，不产生任何网络请求。
- **FR-002 开关入口**：出货配置与快捷面板各一处入口，两处读写同一份状态；切换生效条件见【待核实】。
- **FR-003 端点白名单**：仅白名单内主机允许连接；白名单为空 = 功能整体不可用（等效关闭）。
- **FR-004 请求时机**：本地候选已就绪之后才发起；请求不占用输入处理的时间片。
- **FR-005 超时静默放弃**：超过阈值（默认 300 ms，可配）即放弃本次结果，不重试、不提示、不影响本地候选上屏。
- **FR-006 候选呈现可区分**：云端词与本地词在呈现上可区分；本地词顺序与编号不受影响。
- **FR-007 选词与上屏**：云端词的选中/上屏语义见 US6；插入不得破坏数字键与翻页选词的既有语义。
- **FR-008 隐私最小化**：只发送当前拼音片段的最小必要形式；不含设备指纹、账号标识、应用清单、位置、剪贴板内容。
- **FR-009 无遥测**：不实现埋点、崩溃上报、行为统计、更新检查。
- **FR-010 首次开启明示**：用户第一次开启时，用一句人话说明"将把当前拼音片段发往你自己配置的服务器"，需一次确认。
- **FR-011 断网不排队**：不可用时丢弃机会而非累积任务；不重试风暴、不留待重放。
- **FR-012 黑名单条款**：ADR 0030 决策 4 与研究报告证据里的第三方（搜狗）端点清单，
  **永远不得**作为连接目标，也不得进入默认配置；白名单若含黑名单主机 → 拒绝生效并给出原因。

## 非功能需求

- **NFR-001 不新增常驻进程**：常驻进程数仍为 **1**；云候选不得带来第二个常驻进程。
- **NFR-002 内存**：常驻内存仍 **< 40 MB**，不因本功能破线。
- **NFR-003 空闲 CPU**：空闲 CPU 仍 **< 0.1%（单核）**；功能关闭态必须与上线前等价。
- **NFR-004 输入延迟**：开启态下本地候选出现与上屏不得增加可感知延迟；网络在旁路。
- **NFR-005 许可证**：保持 GPLv3 兼容，**不新增第三方依赖**。
- **NFR-006 不改 librime 子模块**：引擎源码保持不动。
- **NFR-007 可见文案**：用户可见字符串保持简体中文。

## 验收标准

| # | 用例 | 通过条件 |
|---|---|---|
| AC-01 | 关闭态零请求（US2/FR-001） | 全输入序列下出向请求数 = 0 |
| AC-02 | 断网降级（US4） | 本地候选与上屏无异常，无重试风暴 |
| AC-03 | 超时降级（US4/FR-005） | 阈值内未返回即静默放弃，无可感知延迟 |
| AC-04 | 白名单空降级（US3/FR-003） | 不发请求、无云端词、无报错 |
| AC-05 | 云端词生效（US1/FR-006） | 目标片段出现 ≥1 条云端词，本地词条目与相对顺序不变 |
| AC-06 | 选词语义不破坏（US6/FR-007） | 数字键/翻页选词对本地词的指向与上线前一致 |
| AC-07 | 隐私最小化（US5/FR-008） | 抓包字段清单与 spec 附录一致，无身份类字段 |
| AC-08 | 性能基线（NFR-001~003） | 三数字按 ADR 0030 判据命令实测通过 |
| AC-09 | 黑名单（FR-012） | 含黑名单主机的白名单配置被拒绝，且代码无该清单硬编码 |
| AC-10 | 回滚（US7） | 开关/清空白名单两条路径均回到 AC-01 状态 |

## 合规红线（必读）

- 逆向研究所获（`docs/research/sogou-reverse-2026-11/`）**只作规格参考**：用于理解"云候选该有什么表现"
  与"哪些端点绝不能连"。**不得**把搜狗的代码、协议实现细节、私有字段语义、数据或接口约定
  写成本项目的实现依赖，也不得据此复用其任何产物。
- 上屏借用剪贴板是火流猩在本机的既有机制（约 2 秒已知限制），与搜狗的跨设备剪贴板上报是两回事，
  文档与实现**不得混同**（ADR 0030「后果」段）。
- 本协议语义由本项目自行定义，服务端由本项目/用户自建。

## 成功判据

1. AC-01 ~ AC-10 全绿，且有可复跑的自动化或明确的手工验收步骤。
2. 三数字（1 进程 / < 40 MB / 空闲 < 0.1%）实测未破线，关闭态实测与上线前等价。
3. 用户能在两处（出货配置、快捷面板）看到并一致地切换这个开关；白名单为空时功能明确不可用。
4. 代码里找不到任何第三方（含搜狗）端点被当作连接目标；找不到遥测。
5. 一份 ADR 记录本能力的架构取舍（含"不新增常驻进程"如何满足），与 spec/plan 互相链接。

## 【待核实】

1. 开关生效条件：改配置/面板切换后是否需重启常驻服务才生效。
2. 开关与白名单的落地位置：出货配置、用户数据目录、还是本机设置存储。
3. 云端词的选词/上屏是否需要独立通道（不进入引擎候选序列时如何选中）。
4. 现有进程间协议是否已有可复用的异步回填通道，还是必须新增一条应答字段。
5. 首版是否需要账号/鉴权（倾向不需要：自建端点自行决定）。
