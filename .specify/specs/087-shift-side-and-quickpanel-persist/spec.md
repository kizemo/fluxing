# 087 - 快速面板「常驻」不被输入焦点切换打断 + 64 位前端换装闭环 + 裸 Shift 左右方向收尾

## 0. 背景

2026-10-29 用户在 1.1.0 装机后做了一轮真机复测，反馈四条，本条覆盖其中三条：

- **反馈 A（面板）**：勾了「快速面板常驻」之后，**切换到别的窗口再切回来**，快捷设置栏
  **仍然会消失**。上一条（spec 086 / ADR 0015）把这一项补进了输入法自己的弹出菜单，
  用户这回是**真的勾上了**，也**真的还在消失** ⇒ 说明「常驻」这件事只挡住了**一部分**
  自动隐藏行为。
- **反馈 B（换装）**：**64 位程序**里跑的**仍然是旧版输入法**。上一条已定性为「装机时文件
  被占用 ⇒ 留标记 ⇒ 开机补换」，但用户机上**根本没有那次补换的痕迹** ⇒ 换装链路**没闭环**。
- **反馈 C（Shift）**：裸 Shift 上屏候选**左右仍然颠倒**（按左 Shift 上了第 3 个候选）。
  上一条已把「左右」的判定收敛到唯一一处，且经**运行时探针**证明接收侧**完全正确**
  ⇒ 剩下的差异**不在「哪一处写反了」**，而在「程序听到的左右」与「手上的左右」不是一回事。
- **反馈 D（CapsLock）**：**不是缺陷**。英文模式下按 CapsLock 进入**大写英文输入**、
  不切回中文，是输入引擎的**既定正确行为**；上一轮复测单在这一处的**口径有误**。

⇒ 本条的形状因此不对称：**面板**与**换装**是「事实清楚、修法已定」⇒ 直接修；
**Shift** 是「事实还差一条」⇒ 本条**只取事实、不改判定**（宪法 R1）。
**CapsLock** 不改码，只写清语义 + 修正复测口径。

## 1. 目标

1. 勾上「快速面板常驻」之后，快捷设置栏**只在用户自己明确要求时**才收起，不再因为
   输入焦点离开而消失。
2. 「明确的手势仍然能收起」这件事**不被上一条目标牵连**（Esc、收起快捷键、点菜单项、
   关掉「常驻」本身，都必须照旧有效）。
3. 64 位程序里的输入法能真正换成新版本；当场换不掉时，**开机自动补齐这条链路要真的跑通**，
   且失败必须**留痕**，不许静默跳过。
4. 裸 Shift 左右方向：把「程序听到的左右」与「手上的左右」之间的差异**取成一条实测事实**，
   并给出**二选一**的修复形态判据。本条**不猜修法**。
5. CapsLock 的既定语义写清楚；上一轮复测单的**口径**改对。

## 2. 用户故事

- **US087-A**：作为用户，我勾上「快速面板常驻」之后，切到别的窗口再切回来，
  快捷设置栏**还在**。（验收 SC-087-1）
- **US087-B**：作为用户，我仍然可以用明确的手势收起快捷设置栏，不受「常驻」影响。
  （验收 SC-087-2）
- **US087-C**：作为用户，我的 64 位程序里跑的是**新版本**输入法；换装失败时我**看得见痕迹**。
  （验收 SC-087-3 / SC-087-4）
- **US087-D**：作为维护者，裸 Shift 左右方向的**下一步动作由事实决定**，而不是由推测决定。
  （验收 SC-087-5 / SC-087-6）
- **US087-E**：作为用户，我按 CapsLock 后的行为**可预期**，复测单不再给出误导性的步骤。
  （验收 SC-087-7）

## 3. 功能需求

- **FR-087-A（US087-A）**：勾选「常驻」之后，**任何不是用户明确手势**的收起行为，
  都不得隐藏快捷设置栏。
- **FR-087-B（US087-B）**：用户明确手势（收起快捷键、Esc、点面板菜单项、关掉「常驻」本身）
  在「常驻」开启时**仍然有效**。
- **FR-087-C（US087-C）**：装包时，新版本必须落到**最终会被加载的那一处**；当场落不进去时，
  必须留下**明确标记**，并由**开机自动补齐**这一步真正替换成功。
- **FR-087-D（US087-C）**：换装链路的**任何一步**失败都不许**静默跳过**；至少要留下
  可供追查的痕迹（标记文件 / 任务登记 / 日志行）。
- **FR-087-E（US087-D）**：裸 Shift 左右方向的事实必须来自**一次真实按键的观测记录**，
  不得由代码推断代替。
- **FR-087-F（US087-D）**：观测结论必须能**二选一**地映射到两种互斥的修复形态
  （「按物理位置判定」/「提供左右互换开关」），使下一步动作无需再猜。
- **FR-087-G（US087-E）**：CapsLock 的既定语义必须写进用户可见文档；上一轮复测单中
  「在 CapsLock 打开状态下测选候选 / 翻页 / 切中英 / 切标点 / 切简繁」的步骤**作废**，
  改为**在 CapsLock 关闭状态下**执行。

## 4. 非目标

- **不改**裸 Shift 的左右判定逻辑。本条只交付「事实 + 判据 + 取证工具」，
  方向修正在事实到手后另立条目（宪法 R1：意图与验收先于实现）。
- **不新增进程间通信消息类型**。本条不触碰消息协议本体，三端无需同步。
- **不给输入法弹出菜单加勾选标记**。常显开关的当前状态仍只在托盘图标菜单可见
  （沿用 ADR 0015 D7）；本条**只记录**该缺口。
- **不改输入引擎本体**（上游只读引用，宪法 P3）。
- **不解决**「沙箱权威门禁在本机跑不起来」的环境故障（清单 T19），本条只如实记录。
- 不改 CapsLock 相关的任何行为。

## 5. 验收标准

### 5.1 行为验收

- **SC-087-1（US087-A）**：勾选「快速面板常驻」→ 切换到另一个窗口 → 切回来 ⇒
  快捷设置栏**仍然可见**。
- **SC-087-2（US087-B）**：「常驻」开启时，Esc / 收起快捷键 / 点面板菜单项 /
  关掉「常驻」本身 ⇒ 快捷设置栏**照旧收起**。
- **SC-087-3（US087-C）**：装包之后，64 位程序实际加载的输入法**是本次新版本**；
  若当场被占用而未能替换，则**开机补齐确实发生**（补齐后版本号 / 时间戳可核对）。
- **SC-087-4（US087-C）**：换装链路的每一步都**留痕**：当场失败有标记文件，
  开机补齐有任务登记，补齐失败有日志行；**不存在**「用户机上一个痕迹都没有」的状态。
- **SC-087-5（US087-D）**：裸 Shift 左右方向**有一条来自真实按键的观测记录**，
  记录里同时含「物理位置」与「程序听到的键」两项。
- **SC-087-6（US087-D）**：该观测记录能**二选一**地判定下一步形态，且判据写死在文档里。
- **SC-087-7（US087-E）**：CapsLock 语义已写进用户可见文档；复测单已改为
  **CapsLock 关闭态**执行。

### 5.2 工程验收

- **SC-087-8**：改动文件通过格式检查（基线本就干净的文件保持干净）；整解构建通过；
  全套件通过。
- **SC-087-9**：安装器改动后，对**部署产物**复跑门禁（源绿 ≠ 产物绿）。

### 5.3 取证记录（修复前）

**缺陷 A · 勾了「常驻」仍会消失**

| 环节 | 事实 |
|---|---|
| 1 · 现象 | 用户**勾上了**「快速面板常驻」，面板仍在输入焦点离开时消失 |
| 2 · 已有设防 | 面板**内部**的四条自动隐藏路径（轮询计时器 / 应用整体切换 / 失去焦点 / 定时器回调）**逐条**都有「常驻」判据 |
| 3 · 漏掉的一条 | **输入焦点离开**这条收起动作**不是从面板内部发起的**，而是从输入法前端那侧发过来的 ⇒ 它绕开了面板内部的全部判据 |
| 4 · 为什么难发现 | 「常驻」开关**看起来**是全局生效的 ⇒ 实测时容易得出「开关没生效」的结论，而实际问题在**开关之外** |
| 5 · 排除项 | 面板内部那四条路径、托盘菜单里的勾选回填、切换面板的入口 —— 全部正常 |

⇒ 修复方向：给**这一条**补上「常驻」判据；**不动**面板的收起动作本体
（它同时服务于需要用户明确手势的路径）。

**缺陷 B · 64 位换装没闭环**

| 环节 | 事实 |
|---|---|
| 1 · 现象 | 用户机上 64 位程序里跑的仍是旧版；**连开机补换的痕迹都没有** |
| 2 · 环节一 | 「版本化安装件」的拷贝**不覆盖**已存在的同名文件 ⇒ 每次装机都停在**上一版**的版本化件上 |
| 3 · 环节二 | 开机补换的**任务登记命令**引号断裂 ⇒ 命令行被解析坏 ⇒ **任务根本没被创建**（用户机上两个任务都不存在） |
| 4 · 环节三 | 补换动作内部的拷贝命令**对单个文件是非法用法**（目录通配写法用在了文件目标上） |
| 5 · 结论 | 三处缺陷**叠在同一条链上**，任一处坏掉整条链就断 ⇒ 只查「最后一步」永远看不到前两环 |

⇒ 修复方向：三处同时改；并且**逐环验证**（拷贝 → 任务登记 → 开机执行），
而不是只看最后一步。

**缺陷 C · 裸 Shift 左右颠倒（本条只取事实）**

| 环节 | 事实 |
|---|---|
| 1 · 现象 | 用户实测：左 Shift 上第 3 个候选、右 Shift 上第 2 个 —— 与**修好之前**完全一样 |
| 2 · 接收侧 | 运行时探针直连运行中的服务，证明接收侧**完全正确**（左右分别取到第 2 / 第 3 个） |
| 3 · 发送侧 | 按代码读实，发送侧的左右判定**依赖两项输入**：系统报上来的**键盘编号** + **物理位置编号** |
| 4 · 排除项 | 通道极性、发送端判定逻辑、接收端解码、消息路由、旧进程抢占 —— **逐条排除** |
| 5 · 未闭合 | **操作系统把物理左 / 右 Shift 报成什么**——这一条**只能靠一次真实按键**取到 |

⇒ 两种形态互斥：若操作系统报反 ⇒ 软件无法分辨物理左右 ⇒ 只能提供「左右互换」开关；
若操作系统报对 ⇒ 是翻译层出错 ⇒ 改按物理位置判定即可根治。
**在事实到手前不动代码。**

**缺陷 D · CapsLock（不是缺陷）**

| 环节 | 事实 |
|---|---|
| 1 · 规则 | 英文模式下按 CapsLock 进入**大写英文输入**、**不切回中文**，是输入引擎的既定行为 |
| 2 · 用户裁定 | 用户已确认这是**正确规则**，不作为缺陷处理 |
| 3 · 连带修正 | 上一轮复测单里「CapsLock 打开时测选候选 / 翻页 / 切中英 / 切标点 / 切简繁」的步骤**无意义**（引擎在该状态下整条链不响应）⇒ 口径改为 **CapsLock 关闭态**执行 |

### 5.4 验证证据（修复后）

**面板守卫**

| 项 | 结果 |
|---|---|
| 守卫落点 | 输入法前端上报「输入焦点离开」的那一处（**调用点**加判据），面板的「隐藏」动作本体**未动** |
| 面板内部四条自动路径 | **保持不变**（逐条位置见 `plan.md` §1.1 的发起点表） |
| 需用户手势的五条路径 | **未改动**，行为不变（同上） |

**换装链路**

| 环节 | 修复前 | 修复后 |
|---|---|---|
| 版本化安装件（32 位） | 拷贝**不覆盖**已存在的同名文件 | 改成「带改名的拷贝 + 显式允许覆盖」 |
| 版本化安装件（64 位） | 同上 | 同上 |
| 开机补换任务登记（32 位） | 引号断裂 ⇒ 任务**根本没被创建** | 脚本落到**无空格路径** ⇒ 命令行**不再需要内层引号** |
| 开机补换任务登记（64 位） | 同上 | 同上 |
| 开机补换内部的拷贝 | 目录通配的写法用在了**单个文件**目标上 | 改成**逐文件覆盖式拷贝** |

（精确位置见 `plan.md` §2.2 / §2.3。）

**裸 Shift 取证**

| 项 | 结果 |
|---|---|
| 运行时探针 | 直连**运行中**的服务：参考轮「取第 1 个」→ 第 2 个候选、「取第 2 个」→ 第 3 个候选；实验轮「左」→ 第 2 个候选、「右」→ 第 3 个候选 ⇒ **接收侧正确** |
| 观测工具 | 一个**一次按键即可出结论**的小工具：同时打印「**物理位置**」「**系统听到的键**」「**前端算出的键**」三列（工具位置与用法见 `plan.md` §2.4） |
| 现场数据 | **未取得**（需用户按一下左 / 右 Shift，30 秒窗口）⇒ 本条**不改方向判定** |

### 5.5 遗留（不在本条内）

- **开机补齐的「拷贝源」仍未闭合**：补换脚本内部仍按**开机时**的系统临时目录去定位待替换文件，
  而文件是在**安装期**暂存的 ⇒ 两者可能不是同一处。本条**如实记录为未决项**，
  不写成「已修好」（ADR 0016 Q-087-1 / 清单 T25）。
- 64 位程序的注册项仍指向**未版本化**的那个文件名 ⇒ 版本化安装件装成后，
  仍需「注册」这一步成功改写它才生效；该步骤若失败会退回开机补齐路径。
- **弹出菜单没有勾选标记**：常显开关的当前状态只在托盘图标菜单可见
  （输入法弹出菜单开菜单时**不回填勾选态**，详见 `plan.md` §1.1 的附带发现）。
  补它需要新增「查询状态」的往返消息 ⇒ 协议扩张，留后续条目（沿用 ADR 0015 D7）。
- **CapsLock 打开态下的相关复测**依旧无意义 ⇒ 复测单已改口径，但引擎行为本身不改。
- 沙箱权威门禁在本机**仍跑不起来**（清单 T19）⇒ 本条没有门禁数字可贴，
  不编造。
